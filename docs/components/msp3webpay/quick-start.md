# Быстрый старт

Как принять первый платёж через WEBPAY на сайте с MiniShop3.

## Требования

| Требование | Версия |
| --- | --- |
| MODX Revolution | 3.0+ |
| MiniShop3 | [1.14.0-beta1](https://github.com/modx-pro/MiniShop3/releases/tag/v1.14.0-beta1) и новее |
| PHP | 8.2+ |
| Доступ | номер магазина, секретный ключ, логин и пароль кабинета |
| Сайт | HTTPS на webhook без 301 |

Примеры номеров магазина из тестов пакета в настройки сайта не копируйте.

## Шаг 1: Провайдер modstore и установка пакета

Пакет зашифрован. Без провайдера установка завершится ошибкой `Package provider not found`.

1. **Система → Управление пакетами → Провайдеры** → добавьте **modstore.pro**:
   - URL: `https://modstore.pro/extras/`
   - Email и API-ключ из личного кабинета modstore.pro
2. Убедитесь, что установлен **MiniShop3**.
3. **Управление пакетами** → установите **msp3WebPay** (в **Show Details** укажите провайдер **modstore.pro**).
4. **Управление → Очистить кэш**.

Резолвер создаёт три активных способа.

| Название | Класс |
| --- | --- |
| Оплата через WebPay (карта) | `Msp3WebPay\Payment\WebPayPayment` |
| Оплата через WebPay (ERIP) | `Msp3WebPay\Payment\WebPayEripPayment` |
| Оплата через WebPay (двухстадийная) | `Msp3WebPay\Payment\WebPayTwoStagePayment` |

## Откуда брать ключи {#откуда-брать-ключи}

Номер магазина (`wsb_storeid`) создаётся при регистрации. Его присылает менеджер WEBPAY в письме. В MODX это **`msp3webpay_store_id`**.

Логин и пароль кабинета тоже приходят в письме. Тестовый кабинет: [sandbox.webpay.by](https://sandbox.webpay.by). Боевой: [billing.webpay.by](https://billing.webpay.by). Подробнее: [среда разработки](https://docs.webpay.by/generalInfo/devEnvironment/).

Секретный ключ задаёте сами. Путь из [документации WEBPAY](https://docs.webpay.by/generalInfo/beforeDev/): меню **Настройки**, затем **Компания**, поле **Секретный ключ**. В поле можно любые символы, кроме `&`. В MODX это **`msp3webpay_secret_key`**. Им подписывается заказ и проверяется уведомление.

Для списания холда, отмены и возврата пакет входит в кабинет отдельно. Логин и пароль из письма положите в **`msp3webpay_api_username`** и **`msp3webpay_api_password`**. Без них эти кнопки во вкладке заказа не работают.

В properties способа те же значения можно положить как `store_id`, `secret_key`, `api_username`, `api_password`. Непустые properties перекрывают системные настройки.

Валюта: BYN, USD, EUR или RUB. Настройка **`msp3webpay_test`** включает песочницу `securesandbox.webpay.by`.

## Шаг 2: Куда вписать в MODX

1. **Настройки → Системные настройки**, фильтр **`msp3webpay`**.
2. Для теста включите **`msp3webpay_test`** и вставьте номер магазина и секрет из тестового кабинета.
3. После сохранения: **Управление → Очистить весь кеш**.

Список полей: [Системные настройки](settings).

## Шаг 3: URL уведомления

В кабинете WEBPAY укажите:

```text
https://ваш-домен.ru/assets/components/msp3webpay/webhook.php
```

HTTPS без 301. Покупатель возвращается на `return.php`. Эта страница статус заказа не ставит.

## Шаг 4: Способ оплаты в MiniShop3

1. В админке MiniShop3 откройте **Настройки → Оплаты**.
2. Включите **Оплата через WebPay (карта)**, **Оплата через WebPay (ERIP)** или **Оплата через WebPay (двухстадийная)**.
3. Привяжите способ к доставке.

## Шаг 5: Боевой режим

1. Письмо менеджера с боевым номером магазина. Замените **`msp3webpay_store_id`**.
2. Секрет в боевом кабинете [billing.webpay.by](https://billing.webpay.by), тот же путь: **Настройки → Компания**.
3. Выключите **`msp3webpay_test`**. Страница оплаты будет `payment.webpay.by`.
4. Пропишите webhook из [шага 3](#шаг-3-url-уведомления).
5. Оплата должна уходить с домена, который указан в договоре. Поддомен WEBPAY считает отдельным сайтом.
6. Выключите **`msp3webpay_debug`**.

Холд не делает заказ оплаченным, пока не спишете его во вкладке заказа.
