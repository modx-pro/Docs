# MODX MCP

**MODX MCP** — компонент для подключения внешних ИИ-агентов к **MODX Revolution 3.x** через **Model Context Protocol (MCP)**.

Он предоставляет агенту специализированный интерфейс для работы с MODX: ресурсами, шаблонами, чанками, сниппетами, TV-полями, системными настройками, пользователями, файлами, пакетами и другими сущностями CMS.

> [!WARNING]
> MODX MCP уменьшает технические риски, но не может гарантировать правильность решений самого ИИ-агента.
>
> Агент может неверно понять задачу или выбрать неподходящий способ её выполнения. На рабочих сайтах следует выдавать агенту только необходимые возможности и дополнительно контролировать критические изменения.

Общая схема работы:

```text
Пользователь → ИИ-агент → MODX MCP → MODX
```

Пользовательский интерфейс, сам ИИ-агент и организация его работы находятся за пределами компонента.

## Зачем нужен MODX MCP

Обычный доступ ИИ-агента к серверу позволяет ему работать с файлами, выполнять команды и обращаться к базе данных. Но значительная часть структуры MODX хранится не просто в файлах или таблицах.

MODX MCP позволяет агенту работать именно с сущностями MODX и учитывать связи между ними.

Например, агент может:

- находить ресурсы, шаблоны, чанки, сниппеты, плагины и TV-поля;
- исследовать структуру сайта;
- искать места использования элементов;
- анализировать зависимости между элементами;
- создавать и изменять объекты MODX;
- работать с системными настройками и источниками файлов;
- выполнять массовые операции с предварительной проверкой;
- создавать резервные копии перед изменениями;
- работать с поддерживаемыми дополнениями MODX;
- передавать информацию о выполненных изменениях во внешнюю систему аудита.

В текущей версии реализовано более **180 операций**.

## Работа со структурой MODX

Главное отличие MODX MCP от универсального доступа к серверу — понимание структуры CMS.

Для агента:

- ресурс остаётся ресурсом;
- шаблон — шаблоном;
- чанк — чанком;
- сниппет — сниппетом;
- TV — TV-полем.

Это позволяет сначала исследовать проект и связанные элементы, а уже затем вносить изменения.

Например, перед изменением общего чанка агент может определить, какие шаблоны и другие элементы его используют.

## Граф зависимостей

В MODX MCP входит граф зависимостей элементов.

Он позволяет находить:

- использование чанков и сниппетов;
- связи шаблонов и TV-полей;
- вызовы одних элементов из других;
- отсутствующие зависимости;
- потенциально неиспользуемые элементы;
- части проекта, которые могут быть затронуты изменением.

Граф доступен как через MCP, так и в менеджере MODX.

Подробнее см. раздел [Граф зависимостей](dependency-graph).

## Контроль изменений

MODX MCP рассчитан не только на чтение данных, но и на работу с реальными проектами.

В компоненте предусмотрены:

- разделение операций чтения и изменения;
- предварительная проверка ряда действий;
- резервное копирование перед изменениями;
- режим предварительного просмотра для некоторых массовых операций;
- ограничения для потенциально опасных действий;
- возможность отключения отдельных групп возможностей;
- блокировка параллельных изменяющих операций;
- сохранение настроек при обновлении компонента;
- возможность интеграции с внешним журналом изменений.

Подробнее см. раздел [Безопасность и контроль изменений](safety).

::: warning
MODX MCP уменьшает технические риски, но не может гарантировать правильность решений самого ИИ-агента.

Агент может неверно понять задачу или выбрать неподходящий способ её выполнения. На рабочих сайтах следует выдавать агенту только необходимые возможности и дополнительно контролировать критические изменения.
:::

## Поддерживаемые сущности

MODX MCP позволяет работать с:

- ресурсами и структурой сайта;
- шаблонами;
- чанками;
- сниппетами;
- плагинами;
- TV-полями и их значениями;
- категориями;
- системными настройками;
- контекстами;
- пользователями и группами;
- политиками доступа;
- источниками файлов и медиа;
- пространствами имён;
- пакетами и установленными дополнениями;
- наборами свойств;
- лексиконами.

Также предусмотрена работа с рядом популярных дополнений, включая:

- MIGX;
- miniShop2;
- VersionX;
- VirtualPage.

Подробнее см. раздел [Поддерживаемые дополнения](integrations).

## Совместимость

Эта документация относится к версии компонента для **MODX Revolution 3.x**.

Текущая линия исходников также поддерживает MODX Revolution 2.8.x, однако для MODX 2 используется отдельный транспортный пакет.

Для MODX 3 используется пакет:

```text
modx3mcp-1.1.0-pl.transport.zip
```

## Что потребуется дополнительно

Установка MODX MCP устанавливает только MODX-часть системы.

Для полноценной работы необходимо отдельно настроить внешний контур:

1. установить MODX MCP;
2. получить API-токен;
3. подключить MCP-клиент;
4. настроить ИИ-агента;
5. определить разрешённые ему операции и правила работы.

В качестве пользовательского интерфейса может использоваться IDE, собственное приложение, система автоматизации, чат или, например, Telegram-бот.

Конкретная схема зависит от используемого ИИ и задач проекта.
