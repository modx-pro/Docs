# Рабочий процесс

## Черновик и опубликовано

| Слой | Где хранится | Кто видит |
| --- | --- | --- |
| Черновик | `draft_json` в `pb_pages` | Редактор, preview |
| Опубликовано | `published_json` + `published_revision` | Сниппет `[[!PageBuilder]]` |

`modResource.content` PageBuilder не заполняет.

## Сохранение и revision

Клиент шлёт `mgr/page/save` с текущим `revision`. Сервер сравнивает revision. При расхождении возвращает `revision_conflict`, клиент перезагружает документ.

Перед publish клиент валидирует обязательные поля и открывает инспектор на первой проблемной секции.

## Публикация и unpublish

`mgr/page/publish` копирует черновик в published snapshot, инкрементирует revision, сбрасывает render cache ресурса.

`mgr/page/unpublish` очищает published snapshot. Черновик не трогается.

## Корзина на странице (Free)

Удалённые секции попадают в **Корзину** (`document.trash[]` в черновике).

| Действие | Поведение |
| --- | --- |
| В корзину | Секция в `trash`, сохраняется `_trashIndex` для восстановления |
| Восстановить | Секция на прежний index (или в конец) |
| Удалить навсегда | Окончательное удаление из `trash` |
| Восстановить все / очистить | Массовое восстановление или окончательное удаление с подтверждением |

События: `pbOnBeforeTrash`, `pbOnAfterTrash`.

Параллельно плагин на `pbOnAfterSave` синхронизирует `pb_basket_items` для [глобальной корзины CMP](cmp#basket-pro) (Pro).

## Копирование и дублирование

**Копировать секции** вызывает processor `mgr/copy/sections`. Укажите ID ресурса-источника. Нужны права save на оба ресурса. События: `pbOnBeforeCopySections`, `pbOnAfterCopySections`.

**Дублировать** в outline создаёт копию с новым `id` в черновике. Сохраните черновик, чтобы зафиксировать изменения на сервере.

## Отмена и повтор

История действий в редакторе живёт до сохранения черновика на сервер.

## Превью черновика

Кнопка **Preview** во вкладке или URL `preview.php` с подписанным токеном (`pagebuilder_preview_secret`). Подробнее: [Вывод на сайте → Превью](frontend#prevyu-chernovika).

## Кеш рендера на фронте

После publish или unpublish кеш раздела `pagebuilder/{resourceId}` сбрасывается. Если вы правите chunks или plugin на render, опубликуйте снова или очистите кеш MODX.

## Fake-данные

При `pagebuilder_fake_enabled = 1` в инспекторе кнопка **Fake** заполняет поля детерминированными демо-данными (`mgr/section/fake`).
