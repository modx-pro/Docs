# Быстрый старт

Установите пакет, впишите ключи и укажите webhook.

## Требования

| Требование | Версия |
| --- | --- |
| MODX Revolution | 3.0+ |
| MiniShop3 | 1.14.0-beta1 и новее |
| PHP | 8.2+ |
| Расширения PHP | `ext-curl`, `ext-json` |
| pdoTools 3.x | только для чанка `tpl` сниппета `cdekPayBindings` |
| Доступ | логин магазина, боевой и тестовый секреты |
| Сайт | HTTPS на webhook без 301 |

Публичного номера тестовой карты нет. Логин `test` и ключ `secret_key_123` из OpenAPI: примеры подписи, не данные магазина. Живой адрес `secure.cdekfin.ru` на них отвечает `403`. В модуле CDEK Pay для Bitrix тест подтверждают кнопками «Успешная оплата» и «Неуспешная оплата», не номером карты.

## Шаг 1: Провайдер modstore и установка пакета

1. **Система → Управление пакетами → Провайдеры** → добавьте **modstore.pro**:
   - URL: `https://modstore.pro/extras/`
   - Email и API-ключ из личного кабинета modstore.pro
2. Убедитесь, что установлен **MiniShop3**.
3. **Управление пакетами** → установите **msp3CDEKPay** (в **Show Details** укажите провайдер **modstore.pro**).
4. **Управление → Очистить кэш**.

Резолвер создаёт два активных способа.

| Название | Класс |
| --- | --- |
| Оплата через CDEK Pay | `Msp3CDEKPay\Payment\CdekPayPayment` |
| Оплата через CDEK Pay (СБП QR) | `Msp3CDEKPay\Payment\CdekPaySbpPayment` |

## Откуда брать ключи {#откуда-брать-ключи}

Логин магазина лежит в личном кабинете на странице магазина. В инструкциях CDEK Pay это **Настройки → Редактировать магазин**, поле **Логин**. В MODX это **`msp3cdekpay_login`**.

Секреты лежат в **Интеграция → Настройка API**:

| Поле в кабинете | Настройка MODX | Когда |
| --- | --- | --- |
| Test Secret Key | `msp3cdekpay_test_secret_key` | Тест. Уведомления с валютой `TST` |
| Secret Key | `msp3cdekpay_secret_key` | Бой. Уведомления с валютой `RUR` |

Если поле в кабинете пустое, задайте ключ сами и впишите то же значение в MODX. Латиница, не короче 11 символов, разный регистр и хотя бы одна цифра.

Трёх системных настроек достаточно. Свойства способа перекрывают их для `send()`, webhook и вкладки. Порядок и прежние ключи: [Системные настройки](settings#логин-и-секреты).

При **`msp3cdekpay_test_mode`** = Да запросы идут в тестовый API, валюта `TST`, секрет тестовый. При значении Нет валюта `RUR` и боевой секрет.

## Шаг 2: Куда вписать в MODX

1. **Настройки → Системные настройки**, фильтр **`msp3cdekpay`**.
2. Для теста: **`msp3cdekpay_test_mode`** = Да, логин магазина и Test Secret Key.
3. После сохранения: **Управление → Очистить весь кэш**.

Список полей: [Системные настройки](settings).

## Шаг 3: URL уведомления {#шаг-3-url-уведомления}

В кабинете откройте **Интеграция → Настройка API** и вставьте:

```text
https://ваш-домен.ru/assets/components/msp3cdekpay/webhook.php
```

HTTPS без 301. Один адрес на магазин. Обработчик ждёт JSON с объектом `payment`. Пустой запрос и обычная форма отвечают `400`.

## Шаг 4: Способ оплаты в MiniShop3

1. В админке MiniShop3 откройте **Настройки → Оплаты**.
2. Включите **Оплата через CDEK Pay** или **Оплата через CDEK Pay (СБП QR)**.
3. Привяжите способ к доставке.

## Шаг 5: Боевой режим

1. Магазин в CDEK Pay и боевой Secret Key. Касса в кабинете, если нужны чеки.
2. **`msp3cdekpay_test_mode`** = Нет. Логин и **`msp3cdekpay_secret_key`**.
3. Тот же webhook из [шага 3](#шаг-3-url-уведомления).
4. Контрольный платёж. Попытка должна стать оплаченной. Заказ получит статус из `ms3_status_paid`.
5. Выключите **`msp3cdekpay_debug`**.
