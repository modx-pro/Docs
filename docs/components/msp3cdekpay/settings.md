# Системные настройки msp3CDEKPay

Ключ в MODX: `msp3cdekpay_<имя>`. После смены очистите кэш MODX.

Логин и секреты: [Быстрый старт](quick-start#откуда-брать-ключи). Установка: [Быстрый старт](quick-start).

## Логин и секреты {#логин-и-секреты}

Пакет читает учётные данные в два шага: сначала свойства способа оплаты, затем системные настройки `msp3cdekpay_*`.

| Сценарий | Откуда логин и секреты |
| --- | --- |
| Оформление заказа (`send()`) | свойства способа, затем `msp3cdekpay_*` |
| Пакетный `webhook.php` | свойства активных способов, затем `msp3cdekpay_*` |
| Вкладка заказа (sync, возврат, блок, чеки) | свойства способа заказа, затем `msp3cdekpay_*` |

Пустое свойство не перекрывает системную настройку. Пакет берёт следующий ключ в строке таблицы ниже, пока значение не найдётся.

| Назначение | Ключи в свойствах способа | Системная настройка |
| --- | --- | --- |
| Логин | `login`, `user_name` | `msp3cdekpay_login` |
| Тестовый секрет | `test_secret_key`, `test_secret` | `msp3cdekpay_test_secret_key` |
| Боевой секрет | `secret_key`, `secret`, `webhook_secret` | `msp3cdekpay_secret_key` |

Для обычного магазина достаточно трёх системных полей из [быстрого старта](quick-start#откуда-брать-ключи). Свойства способа нужны, если у двух способов CDEK Pay разные кабинеты или секреты.

| Ключ | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `msp3cdekpay_login` | text | пусто | Логин магазина |
| `msp3cdekpay_secret_key` | password | пусто | Боевой секрет. Уведомления с валютой `RUR` |
| `msp3cdekpay_test_secret_key` | password | пусто | Тестовый секрет. Тестовый режим и уведомления с `TST` |
| `msp3cdekpay_test_mode` | bool | да | Да: тестовый API и валюта `TST`. Нет: бой и `RUR` |
| `msp3cdekpay_payment_receipt` | bool | нет | Чек в заказе на оплату. Нужны email покупателя и касса |
| `msp3cdekpay_vat_type` | list | `none` | НДС позиции чека |
| `msp3cdekpay_payment_method` | list | `full_payment` | Признак способа расчёта |
| `msp3cdekpay_payment_object_delivery` | number | `4` | Предмет расчёта для строки доставки |
| `msp3cdekpay_link_life_time` | number | `0` | Минуты жизни ссылки. `0` значит без таймера |
| `msp3cdekpay_qr_life_time` | number | `15` | Минуты жизни QR СБП при оплате заказа. Значение меньше 2 пакет заменяет на 15 |
| `msp3cdekpay_success_url` | text | пусто | Куда вернуть после оплаты. Пусто: страница благодарности MS3 |
| `msp3cdekpay_fail_url` | text | пусто | Куда вернуть после ошибки. Пусто: та же страница с `payment_fail=1` |
| `msp3cdekpay_debug` | bool | нет | Тело заказа на оплату и успешный webhook в лог. На бою выключите |

`vat_type`: `none`, `vat0`, `vat5`, `vat7`, `vat10`, `vat20`, `vat22`, `vat105`, `vat107`, `vat110`, `vat120`, `vat122`.

`payment_method`: `full_payment`, `full_prepayment`, `partial_payment`, `credit`, `credit_payment`.

## Откуда email и телефон

### Заказ на оплату

Поле `user_email` в запросе CDEK Pay заполняется только из адреса заказа (`msOrderAddress` или связь `Address`). Другие поля заказа пакет для этого не использует.

Телефон уходит, только если после нормализации получается 11 цифр на `7` или `8`. Из 10 цифр пакет делает номер `7` и эти цифры. Номер `8xxxxxxxxxx` заменяется на `7xxxxxxxxxx`. Источник: тот же адрес заказа.

### Чек 54-ФЗ

Email для чека ищется по цепочке:

1. адрес заказа (`msOrderAddress` или `Address`);
2. `order.properties.email`;
3. `msCustomer.email`, если задан `customer_id`.

Телефон в чеке: те же правила нормализации, из адреса заказа.
