# FAQ

## HTTP 403 при создании платежа

Логин `test` и ключ `secret_key_123` из примеров OpenAPI живой API не принимает. Нужны логин магазина и секрет из кабинета CDEK Pay. Где взять: [Откуда брать ключи](quick-start#откуда-брать-ключи).

## Webhook 400 Invalid JSON

Обработчик ждёт JSON с объектом `payment`. Пустая проверка адреса и обычная форма не подойдут.

Адрес:

```text
https://ваш-домен.ru/assets/components/msp3cdekpay/webhook.php
```

Неверная подпись отвечает `401`. Для валюты `TST` нужен тестовый секрет, для `RUR` боевой.

Если MiniShop3 не зарегистрировал сервис `ms3_payment_lifecycle`, ответ `500`. Конфликт при обновлении попытки (не «попытка не найдена») даёт `409`. Неизвестный тип уведомления пакет игнорирует с `200` и телом `ignored`. Полный список кодов: [Webhook](integration#webhook).

## Нет ключа ссылки

Платёж не создался или попытка не записалась. Без ключа ссылки нечего блокировать и не с чем сверять список платежей. Возврат и чек полного расчёта ждут ещё id платежа из webhook. Это другое поле, не ключ ссылки.

## Редирект на тестовом домене

HTTP часто отвечает `301` и теряет тело POST. Для webhook нужен HTTPS без редиректа, в том числе на доменах вида `*.test`.
