# SEO шаблоны

SEO-шаблон — правило, по которому собираются title, H1, description и текст для страниц фильтрации. Одно правило работает на всех значениях фильтра: шаблон для ключа `vendor` даёт заголовок и для «Acme», и для любого другого производителя.

## Шаблон или индивидуальный текст

| Задача | Где решается |
|---|---|
| Заголовок по формуле для всех значений фильтра | SEO-шаблон, эта страница |
| Свой текст под одну конкретную подборку — определённый бренд, определённый цвет | [Индивидуальные SEO](seo-pages) |

Шаблон не различает значения: он подбирается по набору ключей, а какие значения выбрал посетитель, на выбор шаблона не влияет. Заполненные поля индивидуальной записи перекрывают шаблон, незаполненные продолжают браться из него.

## Создание шаблона

**mFilter → SEO шаблоны → Добавить**.

| Поле | Что задаёт |
|---|---|
| **Название** | Только для списка в админке |
| **Страница** | Шаблон действует на этой странице. Пустое поле — глобальный шаблон, на всех страницах |
| **Ключи фильтров** | Обязательное. Ключи, при которых шаблон срабатывает: `vendor`, `color`. Вводятся по одному, через Enter |
| **Шаблон H1** | Заголовок страницы |
| **Шаблон Title** | Тег `<title>` |
| **Шаблон Description** | Мета-описание |
| **Шаблон текста** | SEO-текст под выдачей |
| **Приоритет** | Разрешает ничью между шаблонами. Меньше — раньше. От 0 до 100 |
| **Активен** | Выключенный шаблон не участвует в подборе |

Шаблон без ключей фильтров не сохранится, а если такая запись попадёт в базу в обход админки — не сработает никогда. «Общего шаблона на всё» не существует; роль запасного варианта играет [поведение без шаблона](#esli-shablon-ne-podobran).

## Как подбирается шаблон

Ключи выбранных фильтров сравниваются с полем «Ключи фильтров» в четыре прохода. Первый подошедший шаблон и применяется:

1. шаблоны этой страницы, у которых набор ключей совпал точно;
2. шаблоны этой страницы, у которых совпал хотя бы один ключ;
3. глобальные шаблоны с точным совпадением;
4. глобальные шаблоны с совпадением хотя бы одного ключа.

Порядок проходов важнее приоритета: страничный шаблон обойдёт глобальный, а точное совпадение — частичное, каким бы ни был номер. Приоритет решает, какой из шаблонов возьмётся, когда в одном проходе подошли несколько.

Частичное совпадение означает, что шаблон для `vendor` применится и к странице, где выбраны `vendor` и `color`. Чтобы у такой пары был свой заголовок, заведите отдельный шаблон с обоими ключами — он выиграет на первом проходе.

## Плейсхолдеры

### Значения фильтров

Значение подставляется по ключу фильтра, без префикса.

| Плейсхолдер | Что подставит |
|---|---|
| `{$vendor}` | Все выбранные значения через запятую |
| `{$vendor_first}` | Только первое значение |
| `{$vendor_count}` | Сколько значений выбрано |

Диапазон приходит одним значением, а не двумя границами: `{$price}` даст «1000 — 5000», а при одной границе — «от 1000» или «до 5000». Слова и тире берутся из лексикона `mfl_seo_range_from`, `mfl_seo_range_to`, `mfl_seo_range_separator`.

### Поля страницы

Поля ресурса доступны под своими именами: `{$pagetitle}`, `{$longtitle}`, `{$description}`, `{$introtext}`, `{$id}`. TV страницы — по имени TV.

### Сайт

`{$site_name}` — системная настройка `site_name`.

::: warning Числа найденных товаров в шаблоне нет
SEO собирается в самом начале запроса, когда выборка ещё не сделана, поэтому подставить в заголовок количество найденного нечем. Число появляется позже — его выставляет сниппет `mFilter`, и выводит чанк обёртки строкой «Найдено: N». В шаблоне ресурса оно доступно как `{$_pls['mfilter.total']}` — но только ниже вызова сниппета.
:::

## Модификаторы

Модификатор пишется через точку после ключа: `{$vendor.gen}`.

### Падежи

| Модификатор | Падеж |
|---|---|
| `.nom` | Именительный |
| `.gen` | Родительный |
| `.dat` | Дательный |
| `.acc` | Винительный |
| `.ins` | Творительный |
| `.pre` | Предложный |

Множественное число — те же имена с суффиксом: `.gen_plural`, `.dat_plural` и так далее.

Формы берутся из [Словоформ](word-forms). Если слова там нет, подставится исходное значение — без ошибки и без записи в лог.

### Обработка текста

| Модификатор | Что делает |
|---|---|
| `.lower`, `.upper` | Нижний и верхний регистр |
| `.ucfirst`, `.lcfirst` | Первая буква заглавная или строчная |
| `.strip` | Убирает HTML-теги |
| `.trim` | Убирает пробелы по краям |
| `.escape` | Экранирует кавычки и угловые скобки |

Неизвестный модификатор ошибки не вызывает — значение подставится как есть. Поэтому опечатка в `{$vendor.gne}` выглядит как «падеж не применился».

## Условия

Блок `{if $ключ}…{/if}` выводит содержимое, только когда значение непустое:

```
{$pagetitle} {if $color}цвета {$color.gen}{/if}
```

Внутри блока работают те же плейсхолдеры и модификаторы.

::: tip Пробелы
Перед сборкой парсер схлопывает подряд идущие пробелы и переносы строк в один пробел, а края обрезает. Разметку многострочного SEO-текста это не портит, но пустые строки между абзацами исчезнут — разделяйте абзацы тегами.
:::

## Примеры шаблонов

### Производитель

Ключи фильтров: `vendor`

```
Title: {$vendor} — купить в {$site_name}
H1: {$vendor}
Description: {$vendor.nom} в наличии. Доставка по всей России.
```

### Производитель и цвет

Ключи фильтров: `vendor`, `color`

```
Title: {$vendor} {$color.gen} цвета — купить | {$site_name}
H1: {$vendor} {$color.gen} цвета
```

Шаблон выиграет у предыдущего на странице, где выбраны оба фильтра: точное совпадение рассматривается раньше частичного.

### Диапазон цен

Ключи фильтров: `price`

```
Title: {$pagetitle} {$price} рублей
H1: {$pagetitle}, {$price}
```

## Если шаблон не подобран

Заголовки собираются из названия страницы и выбранных значений:

- **H1** — «Название страницы - Значения»;
- **Title** — то же плюс « | Название сайта»;
- **Description** — описание страницы плюс те же значения.

Значения при этом превращаются в подписи: раздел подставляется своим названием, производитель MiniShop3 — именем, числовое значение TV — подписью из индекса.

## Индексация

Поля «не индексировать» у шаблона нет: страницы закрываются системными настройками.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `mfilter.seo_noindex_filtered` | Нет | Закрывает все отфильтрованные страницы разом |
| `mfilter.seo_max_filters` | 2 | Закрывает страницу, где выбрано больше указанного числа фильтров |
| `mfilter.seo_max_values` | 1 | Закрывает страницу, где у одного фильтра выбрано больше указанного числа значений |

Диапазон считается одним фильтром, хотя в адрес попадает двумя границами. А вот в подсчёте значений границы считаются порознь — поэтому `seo_max_values` не закрывает страницу с диапазоном.

Индивидуальный текст снимает закрытие: страница, для которой его написали, индексируется, даже если попала под лимиты. Настройка `mfilter.seo_noindex_filtered` сильнее — она закрывает страницу и при заполненной индивидуальной записи.

## Canonical

Адрес вычисляется, в шаблоне его не задают.

- Открытая для индексации страница получает canonical на саму себя — отфильтрованный адрес без номера страницы, сортировки и лимита;
- закрытая — canonical на страницу без фильтров.

Адрес всегда абсолютный.

## Программный доступ

```php
$mfilter = $modx->services->get('mfilter');
$seoBuilder = $mfilter->getSeoBuilder();

$seoData = $seoBuilder->build($resourceId, $filters);
// [
//     'h1' => 'Acme',
//     'title' => 'Acme — купить в Название сайта',
//     'description' => 'Acme в наличии...',
//     'text' => '<p>SEO текст...</p>',
//     'canonical' => 'https://site.ru/catalog/vendor--acme/',
//     'noindex' => false
// ]
```

Для несуществующего ресурса `build()` вернёт пустой массив.

| Метод | Что делает |
|---|---|
| `shouldNoindex(array $filters): bool` | Попадает ли набор фильтров под лимиты индексации |
| `getCanonical(int $resourceId, array $filters): string` | Canonical для набора фильтров |
| `clearCache(): void` | Сбрасывает кэш загруженных шаблонов |

## Вывод на фронтенде

SEO-данные попадают в MODX-плейсхолдеры `mfilter.seo.*`. В Fenom доступ к ним — через массив `$_pls`. Плейсхолдеры устанавливаются плагином на каждой странице фильтрации, а на нефильтрованных страницах — это пустые строки (кроме `noindex` — `false`).

Вставьте в шаблон ресурса каталога (`<head>` и `<body>`):

```html
<title>{$_pls['mfilter.seo.title'] ?: $_modx->resource.pagetitle}</title>
<meta name="description" content="{$_pls['mfilter.seo.description'] ?: $_modx->resource.description}">

{if $_pls['mfilter.seo.canonical']}
    <link rel="canonical" href="{$_pls['mfilter.seo.canonical']}">
{/if}

{if $_pls['mfilter.seo.noindex']}
    <meta name="robots" content="noindex, follow">
{/if}

<h1 data-mfilter-h1>{$_pls['mfilter.seo.h1'] ?: $_modx->resource.pagetitle}</h1>

<div data-mfilter-seo-text{if !$_pls['mfilter.seo.text']} style="display:none"{/if}>
    {$_pls['mfilter.seo.text']}
</div>
```

Логика фолбэков: если фильтров нет, `mfilter.seo.*` пустые, и `?:` возвращает стандартное значение ресурса (`pagetitle`/`description`). Как только фильтры применены — SEO-шаблон подставляет свой title/H1/description.

::: warning Маркеры для AJAX
Атрибуты `data-mfilter-h1` и `data-mfilter-seo-text` (или классы `h1.mfilter-h1` и `.mfilter-seo-text`) **обязательны**: без них JS не найдёт элементы при AJAX-фильтрации, и они обновятся только после `F5`. Класс `mfilter-h1` срабатывает только на теге `<h1>` — на другом теге нужен атрибут. Меты `title`, `description`, `canonical`, `robots` в `<head>` JS обновляет по стандартным селекторам — маркеры не нужны.
:::

После обновления JS вызывает событие `mfilter:seoUpdate` — его можно слушать, если на странице есть свои элементы с SEO-данными.
