# Быстрый старт

Фасетная фильтрация каталога MiniShop3 — от установки до проверки на сайте.

## Шаг 1: Установка

Нужны MODX 3.x и PHP 8.0 или новее. Зависимости **pdoTools** от 3.0.2-pl и **VueTools** от 1.0.0-beta1 установщик докачает сам — вручную их ставят, только если провайдер не ответил.

1. Установите mFilter через **Установщик → Загрузить дополнения**
2. Желательно установить **Scheduler** — он берёт на себя фоновые задачи: пересборку индекса фасетов, синхронизацию индекса каждые пять минут, прогрев кэша, карту сайта
3. Откройте **Приложения → mFilter** и нажмите **«Построить индекс»** в правом верхнем углу

Без индекса фильтрация работает в медленном запасном режиме. Если Scheduler установлен, индекс соберётся в фоне сам.

## Шаг 2: Создание набора фильтров

1. Откройте **Приложения → mFilter → Наборы фильтров**
2. Нажмите **Добавить набор**
3. Введите название (например, «Каталог электроники») и проверьте, что включён флажок **Активен**

### Добавление фильтров

В секции **Фильтры** нажмите **+ Добавить фильтр**. Достаточно ключа и заголовка — источник и тип подставятся сами:

| Ключ | Источник подставится | Тип | Заголовок |
|------|----------------------|-----|-----------|
| `vendor_id` | miniShop3 — данные товаров | Производители | Производитель |
| `color` | miniShop3 — опции | Цвета | Цвет |
| `size` | miniShop3 — опции | Стандартный | Размер |
| `price` | miniShop3 — данные товаров | Числовой (диапазон) | Цена |
| `made_in` | miniShop3 — данные товаров | Стандартный | Страна производства |

Типы **Производители** и **Цвета** доступны только при установленном MiniShop3.

::: tip Когда источник указывают вручную
Автоопределение по ключу различает три источника. Известные поля `msProductData` (`price`, `weight`, `vendor_id`, `made_in`…) дают данные товаров. Остальные ключи — опции, если стоит MiniShop3, и поля ресурса, если его нет.

Для фильтра по TV автоопределение не срабатывает никогда — выберите источник **Template Variables** сами. Вручную источник задают и тогда, когда нужно обойти автоопределение или подключить свой источник.
:::

### Привязка к категориям

Форма набора разделена надвое: слева настройки, справа страницы, к которым набор привязан.

1. В левой колонке, ниже таблицы фильтров и поля «Порядок в списке», оставьте включённым флажок **Наследование на дочерние страницы** — тогда набор сработает во всех вложенных категориях
2. В правой, под заголовком **Страницы каталога**, отметьте корневые категории (например, «Каталог»). Страница, которую уже занял другой набор, помечена меткой «занято»
3. Сохраните набор

[![](https://file.modx.pro/files/6/0/6/6067dabb8993b14f1339d034e080824c.png)](https://file.modx.pro/files/6/0/6/6067dabb8993b14f1339d034e080824c.png)

### Индекс обновляется сам

Сразу после сохранения mFilter достроит индекс фасетов для добавленных ключей — на крупном каталоге это занимает несколько секунд. Индекс обновляется и при сохранении товара в админке.

Руками его пересобирают после массовых импортов и правок в базе мимо MODX.

## Шаг 3: Сниппеты на странице каталога

За образец можно взять готовый шаблон ресурса `core/components/mfilter/elements/templates/catalog.tpl` из комплекта.

Минимальный вариант:

```fenom
{* Сначала mFilter, результат — в переменную *}
{set $mfilterOutput = '!mFilter' | snippet : [
    'element' => 'msProducts',
    'paginator' => 'pdoPage',
    'parents' => $_modx->resource.id,
    'limit' => 24,
    'tpl' => 'tpl.msProducts.row',
    'tplOuter' => 'mfilter.outer'
]}

<aside>
    {'!mFilterForm' | snippet}
</aside>

<main>
    {'!mFilterSelected' | snippet}
    {$mfilterOutput}
</main>
```

Порядок вызовов важен: форма берёт область выборки у `mFilter`. Если вызвать её раньше, она посчитает область сама — по разделам и глубине, мимо выдачи элемента. Числа рядом со значениями тогда разойдутся с тем, что в списке.

Пагинацию выводить отдельно не нужно: mFilter отключает её у `pdoPage` и рисует свою внутри `tplOuter`.

::: tip Хлебные крошки
`{'!mFilterCrumbs' | snippet}` — добавляет в крошки сегменты активных фильтров. Микроразметка Schema.org выводится всегда, JSON-LD — по параметру `&schemaJsonLd=1`.
:::

### Подключение CSS/JS

CSS и JS подключает плагин mFilter — системная настройка `mfilter.register_frontend` включена по умолчанию. Список файлов хранится в `mfilter.frontend_assets` и обновляется вместе с пакетом.

Ползунок диапазона рисует библиотека **noUiSlider**. Она идёт в комплекте и стоит первой в списке файлов. Подключать её с CDN не нужно — вторая копия только мешает.

::: tip Ручное подключение
Если автоподключение мешает (например, нужен свой порядок загрузки) — выключите `mfilter.register_frontend` и подключите CSS/JS вручную. Список файлов смотрите в [Системные настройки → Фронтенд](settings#frontend).

Тогда noUiSlider подключите сами, до `mfilter.slider.js`: без неё фильтры с диапазоном не сломаются, но вместо ползунка останутся два поля «от» и «до», а в консоли появится предупреждение.
:::

## Шаг 4: Базовая стилизация

Внешний вид меняют переопределением классов:

```css
/* Форма фильтров */
.mfilter-form { }

/* Блок одного фильтра */
.mfilter-block { }

/* Заголовок блока: в поставляемом чанке он помечен атрибутом,
   класса на нём нет */
[data-filter-label] { }

/* Элементы фильтра */
.mfilter-item { }
.mfilter-item label { }
.mfilter-count { }

/* Диапазон (слайдер) */
.mfilter-range { }

/* Состояние загрузки */
.mfilter-loading { }
```

## Шаг 5: Проверка работы

1. Откройте страницу категории на сайте
2. Выберите значения в фильтрах

Список обновится через AJAX, а адрес примет вид `/catalog/vendor_id--apple/color--black/`. AJAX работает, если на странице есть форма с атрибутом `data-mfilter`.

Значения в адресе — это алиасы, mFilter собирает их из значений сам. Переименовать алиас можно на вкладке **Алиасы**.

[![](https://file.modx.pro/files/4/5/7/45722f454a195e377ece5fdbece10f35.png)](https://file.modx.pro/files/4/5/7/45722f454a195e377ece5fdbece10f35.png)

Если фильтрация заметно медленная на крупном каталоге — проверьте **индекс фасетов**: **mFilter → Обслуживание → Индекс фасетов** должен показывать статус «Активен».

## Настройка SEO (по желанию)

### SEO-шаблоны

Динамические title, h1 и description задают в **mFilter → SEO шаблоны**.

SEO-шаблон подбирается в четыре захода:

1. точное совпадение набора ключей среди шаблонов этой страницы
2. частичное совпадение там же — достаточно одного общего ключа
3. точное совпадение среди глобальных шаблонов
4. частичное совпадение среди глобальных

Если не подошёл ни один, заголовок и описание собираются из названия страницы и выбранных значений.

Значение фильтра подставляется по ключу, без префикса:

| Плейсхолдер | Что подставит |
|---|---|
| `{$vendor_id}` | все выбранные значения через запятую |
| `{$vendor_id_first}` | только первое значение |
| `{$vendor_id_count}` | число выбранных значений |
| `{$pagetitle}`, `{$longtitle}` | поля страницы под своими именами |

Пример:

```
Title: {$pagetitle} {$vendor_id} {$color} — купить
H1: {$vendor_id} {$color}
Description: {$vendor_id} {$color} в наличии. Доставка по всей России.
```

После точки идёт падеж, а не ключ: `{$vendor_id.gen}` — родительный. Остальные падежи и формы — в [Словоформах](interface/word-forms).

Подробнее: [SEO-шаблоны](interface/seo-templates).

### Словоформы

Склонения значений для SEO-текстов хранятся в **mFilter → Словоформы**: шесть падежей в двух числах плюс формы «где/куда/откуда» для топонимов.

Формы можно сгенерировать автоматически через [Morpher API](settings#morpher-api) — укажите ключ в `mfilter.morpher_api_key`.

Подробнее: [Словоформы](interface/word-forms).

## Альтернативные сценарии

### Без MiniShop3 (pdoResources)

```fenom
{set $mfilterOutput = '!mFilter' | snippet : [
    'element' => 'pdoResources',
    'paginator' => 'pdoPage',
    'parents' => $_modx->resource.id,
    'includeTVs' => 'image,brand',
    'tpl' => 'мой.чанк.ресурса'
]}

{'!mFilterForm' | snippet}
{$mfilterOutput}
```

Чанки `mfilter.grid` и `mfilter.row` из комплекта здесь не подойдут: это карточки товара MiniShop3 — с ценой, артикулом и заглушкой изображения. На обычных ресурсах они выведут пустые карточки, поэтому нужен свой чанк.

### Отдельные формы для разных фильтров

```fenom
{* Сайдбар: только vendor + color + price *}
{'!mFilterForm' | snippet : [
    'filters' => 'vendor_id,color,price',
    'sortByCount' => 1
]}

{* Отдельно: панель размеров над товарами *}
{'!mFilterForm' | snippet : [
    'filters' => 'size',
    'tplOuter' => '@INLINE <form{$formAttrs}><div class="size-bar">{$filters}</div></form>'
]}
```

В своей обёртке оставьте `<form{$formAttrs}>`: именно на эту строку атрибутов навешиваются `data-mfilter*`, по которым работает AJAX. Блоки фильтров приходят в переменной `filters`.

### Переключение вида: сетка и список

```fenom
<div class="view-toggle">
    <a href="?tpl=tpl1" data-mfilter-tpl="tpl1">Сетка</a>
    <a href="?tpl=tpl2" data-mfilter-tpl="tpl2">Список</a>
</div>

{'!mFilter' | snippet : [
    'element' => 'msProducts',
    'paginator' => 'pdoPage',
    'parents' => $_modx->resource.id,
    'tpl' => 'mfilter.grid',
    'tpls' => ['tpl1' => 'mfilter.grid', 'tpl2' => 'mfilter.row']
]}
```
