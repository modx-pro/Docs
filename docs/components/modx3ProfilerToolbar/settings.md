# Системные настройки

В системных настройках MODX отфильтруйте пространство имён `modx3profilertoolbar`. Пункт меню пакет не создаёт.

## Ключи

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `modx3profilertoolbar.enabled` | Нет | Включает плагин. На `OnMODXInit` вызываются `start()` и `replaceParser()`. При «Нет» плагин выходит до сбора. |
| `modx3profilertoolbar.sampling_rate` | `100` | Процент запросов, для которых `start()` доходит до сбора. Ниже 100 пропущенный запрос панель не получает. При включённом `enabled` `replaceParser()` выполняется и на пропущенном запросе. |
| `modx3profilertoolbar.frontend_toolbar` | Да | Разрешает вставку панели. Нужны контекст `web` и сессия `mgr`. |
| `modx3profilertoolbar.slow_query_ms` | `100` | Порог медленного SQL в миллисекундах. Правило смотрит время строки SQL. Результат в HTML не вставляется. |
| `modx3profilertoolbar.slow_snippet_ms` | `50` | Порог медленного сниппета в миллисекундах. Правило читает события с типом `snippet`. Сбор такие события не добавляет. Панель порог не показывает. |
| `modx3profilertoolbar.cli_enabled` | Нет | При «Да» сбор в CLI не отсекается. Панель вставляется только в контексте `web`. В базу и файл пакет ничего не пишет. |

## Кто видит данные

В HTML попадает JSON текущего запроса: времена, имена собранных тегов и строка с числом SQL. Отдельных текстов запросов и имён плагинов в разметке нет.

Вставку делает только запрос со сессией `mgr`. Ограничьте вход в менеджер.

`sampling_rate` уменьшает число запросов со сбором. Подмену парсера при включённом `enabled` он не отключает.
