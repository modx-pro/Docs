# mSearch

Сниппет для поиска и вывода результатов.

Выводит найденные результаты через pdoTools. Конфигурация pdoFetch фиксирована: произвольные свойства pdoTools (`&where`, `&includeTVs`, `&sortby` и другие) сниппет в pdoFetch **не передаёт**, а набор полей в чанке определяет адаптер. Расширение этого поведения запланировано — см. [issue #16](https://github.com/biz87/mSearch/issues/16).

::: warning Некэшируемый вызов
Сниппет должен вызываться **некэшированно** (с `!`), так как реагирует на поисковый запрос из `$_REQUEST`.
:::

## Параметры

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| **query** | `$_REQUEST[queryVar]` | Поисковый запрос. Если не задан явно — берётся из HTTP-параметра, имя которого указано в `queryVar` |
| **queryVar** | `mse_query` | Имя HTTP-параметра, из которого читается поисковый запрос. Проверяется по регулярному выражению `^[a-zA-Z_][a-zA-Z0-9_]*$`; при недопустимом имени — запасной вариант `mse_query` |
| **tpl** | `mSearch.row` | Чанк оформления для каждого результата |
| **tplWrapper** | | Чанк-обёртка для всех результатов |
| **limit** | `10` | Лимит результатов. `0` — без ограничения (полезно для `return=ids`) |
| **toPlaceholder** | | Сохранить результаты в плейсхолдер вместо вывода |
| **contexts** | текущий контекст | Контексты для фильтрации, через запятую (например `web,ru`). Пустая строка оставляет **текущий** контекст; чтобы искать по всем контекстам, передайте `,` |
| **return** | `chunks` | Формат вывода: `chunks`, `ids`, `json`, `data` |

### Параметр return

| Значение | Описание |
|----------|----------|
| `chunks` | Вывод через чанки (по умолчанию) |
| `ids` | Только ID найденных ресурсов через запятую |
| `json` | JSON-массив с данными ресурсов |
| `data` | Массив данных (для использования в других сниппетах) |

## Плейсхолдеры

### Глобальные плейсхолдеры

После выполнения сниппет устанавливает:

| Плейсхолдер | Описание |
|-------------|----------|
| `[[+mse.total]]` | Общее количество найденных результатов |
| `[[+mse.query]]` | Поисковый запрос |

### Плейсхолдеры в чанке tpl

| Плейсхолдер | Описание |
|-------------|----------|
| `[[+id]]` | ID ресурса |
| `[[+pagetitle]]` | Заголовок |
| `[[+longtitle]]` | Расширенный заголовок |
| `[[+introtext]]` | Вводный текст |
| `[[+weight]]` | Релевантность (вес) результата |
| `[[+intro]]` | Весь `introtext` с подсвеченными совпадениями в `<mark>` (HTML-safe) |
| `[[+idx]]` | Порядковый номер в списке |
| *и другие поля ресурса...* | Доступны все поля, которые загрузил pdoFetch |

::: warning Поле content недоступно
Сниппет загружает фиксированный набор полей и не передаёт `content` в чанк — плейсхолдер `[[+content]]` работать не будет. Свойство `&includeContent` сниппет не читает. Возможность запланирована — см. [issue #16](https://github.com/biz87/mSearch/issues/16).
:::

### Плейсхолдеры в чанке tplWrapper

| Плейсхолдер | Описание |
|-------------|----------|
| `[[+output]]` | Все результаты, склеенные подряд |
| `[[+total]]` | Количество результатов |
| `[[+query]]` | Поисковый запрос |

## Примеры

### Базовый вызов

```fenom
{'!mSearch' | snippet}
```

### Со своим чанком

```fenom
{'!mSearch' | snippet : [
    'tpl' => 'mySearchResult',
    'limit' => 20
]}
```

### С обёрткой

```fenom
{'!mSearch' | snippet : [
    'tpl' => 'mSearch.row',
    'tplWrapper' => 'mSearch.wrapper',
    'limit' => 10
]}
```

Чанк `mSearch.wrapper` по умолчанию:

```fenom
<div class="mse-results">
    <div class="mse-results-header">
        <p class="mse-results-info">{'mse_results_found' | lexicon : ['total' => $total, 'query' => $query]}</p>
    </div>
    <div class="mse-results-list">
        {$output}
    </div>
</div>
```

### С пагинацией через pdoPage

Сам `mSearch` постраничную навигацию не делает (не читает `offset`). Пагинация строится так: `mSearch` отдаёт ID найденных ресурсов (`return=ids`, `limit=0`), а `pdoPage` пагинирует по этому списку и формирует навигацию.

```fenom
{'!pdoPage' | snippet : [
    'element' => 'pdoResources',
    'resources' => '!mSearch' | snippet : ['return' => 'ids', 'limit' => 0] | default : '0',
    'sortby' => 'ids',
    'tpl' => 'mSearch.row',
    'limit' => 10
]}

{$_modx->getPlaceholder('page.nav')}
```

::: tip Зачем `default`
Фильтр `| default : '0'` подставляет несуществующий ID, если поиск ничего не нашёл, — иначе `pdoResources` с пустым `resources` выведет все ресурсы.
:::

### Получение только ID

Полезно для передачи в другие сниппеты:

```fenom
{set $ids = '!mSearch' | snippet : [
    'return' => 'ids',
    'limit' => 0
]}

{if $ids}
{'msProducts' | snippet : [
    'resources' => $ids,
    'sortby' => 'ids'
]}
{else}
<p>Товары не найдены</p>
{/if}
```

### Поиск товаров MiniShop3

```fenom
{'!pdoPage' | snippet : [
    'element' => 'msProducts',
    'parents' => 0,
    'resources' => '!mSearch' | snippet : ['return' => 'ids', 'limit' => 0] | default : '999999',
    'sortby' => 'ids',
    'tpl' => 'tpl.msProducts.row'
]}

{$_modx->getPlaceholder('page.nav')}
```

::: tip Фильтр default
Фильтр `| default : '999999'` подставляет несуществующий ID, если поиск не дал результатов. Это предотвращает вывод всех товаров при пустом запросе.
:::

### JSON для AJAX

```fenom
{'!mSearch' | snippet : [
    'return' => 'json',
    'limit' => 5
]}
```

### Своё имя HTTP-параметра запроса

Применяется в двух случаях:

- миграция с платформы, где внешние ссылки уже используют другое имя параметра;
- несколько форм поиска с разной семантикой на одной странице.

```fenom
{'!mSearch' | snippet : ['queryVar' => 'q']}
```

Сниппет прочитает запрос из `$_REQUEST['q']` вместо `$_REQUEST['mse_query']`.

## Чанк по умолчанию

Чанк `mSearch.row`:

```fenom
<div class="mse-result" data-idx="{$idx}">
    <h3 class="mse-result-title">
        <a href="{$id | url}">{$pagetitle}</a>
    </h3>
    {if $intro?}
        <p class="mse-result-intro">{$intro}</p>
    {/if}
    <div class="mse-result-meta">
        <span class="mse-result-date">{$publishedon | date : 'd.m.Y'}</span>
        {if $weight?}
            <span class="mse-result-weight">{'mse_weight' | lexicon}: {$weight | number : 2}</span>
        {/if}
    </div>
</div>
```

## Подсветка результатов

Плейсхолдер `[[+intro]]` — весь `introtext` с подсвеченными совпадениями в `<mark>`. Текст подсвечивается целиком, фрагментации «вокруг совпадения» нет.

`Highlighter` экранирует исходный текст через `htmlspecialchars` до вставки `<mark>` — результат HTML-safe, можно безопасно выводить в чанке без дополнительного `|escape`.

## Фильтрация по контексту

По умолчанию сниппет фильтрует результаты по текущему контексту MODX. Это важно для мультиконтекстных сайтов (например, мультиязычных), чтобы пользователи русского сайта не видели в результатах страницы с английского.

```fenom
{* Поиск только в текущем контексте (по умолчанию) *}
{'!mSearch' | snippet}

{* Поиск в нескольких контекстах *}
{'!mSearch' | snippet : ['contexts' => 'web,ru']}

{* Поиск по всем контекстам *}
{'!mSearch' | snippet : ['contexts' => ',']}
```

## Алгоритм поиска

1. **Разбиение запроса** — запрос разбивается на слова
2. **Обработка алиасов** — применяются синонимы и замены
3. **Морфологический анализ** — для каждого слова ищутся базовые формы
4. **Поиск в индексе** — поиск слов в таблице индекса с фильтрацией по контексту
5. **LIKE-поиск** — дополнительный поиск по полному тексту (`mse_intro`)
6. **Применение бонусов** — добавление веса за точные совпадения и за вхождение всех слов
7. **Сортировка** — результаты сортируются по релевантности

## События

При поиске вызываются события `Searcher`:

- **mseOnBeforeSearch** — перед поиском, можно модифицировать запрос и опции
- **mseOnAfterSearch** — после поиска, можно модифицировать результаты

События вызываются в `Searcher::search()`, поэтому срабатывают одинаково и при использовании сниппета, и при прямом обращении к `$msearch->search()` (например, из своего PHP-кода).
