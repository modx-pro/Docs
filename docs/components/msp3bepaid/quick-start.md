# Быстрый старт

Инструкция по приёму первого платежа через bePaid на сайте с MiniShop3.

## Требования

| Требование | Версия |
| --- | --- |
| MODX Revolution | 3.0+ |
| MiniShop3 | 1.14.0-beta1 и новее |
| PHP | 8.2+ |
| PHP-модуль | `bcmath` |
| Доступ | Shop ID и секретный ключ магазина |
| Сайт | HTTPS на webhook без 301 |

Без `bcmath` пакет не переведёт сумму заказа в мелкие единицы валюты.

## Шаг 1: Провайдер modstore и установка пакета

1. **Система → Управление пакетами → Провайдеры** → добавьте **modstore.pro**:
   - URL: `https://modstore.pro/extras/`
   - Email и API-ключ из личного кабинета modstore.pro
2. Убедитесь, что установлен **MiniShop3**.
3. **Управление пакетами** → установите **msp3BePaid** (в **Show Details** укажите провайдер **modstore.pro**).
4. **Управление → Очистить кэш**.

Резолвер создаёт один способ оплаты.

| Название | Класс |
| --- | --- |
| Оплата через BePaid | `Msp3BePaid\Payment\BePaidPayment` |

## Откуда брать ключи {#откуда-брать-ключи}

Shop ID и секретный ключ — в личном кабинете bePaid. Путь из [документации API](https://docs.bepaid.by/ru/using_api/id_key/):

1. Войдите в кабинет и откройте вкладку **Магазины**.
2. У нужного магазина нажмите **Подробнее**.
3. **Shop ID**: значение в строке **ID**. В MODX это **`msp3bepaid_store_id`**.
4. **Secret Key** откроется по кнопке **Показать секретный ключ магазина** в секции **Идентификационные данные**. В MODX это **`msp3bepaid_secret_key`**.

bePaid проверяет запросы к API и уведомления этими двумя значениями. Без них способ не считается настроенным.

Пакет проверяет подпись уведомления в заголовке `Content-Signature` публичным ключом. Ключ берут в личном кабинете ([документация уведомлений](https://docs.bepaid.by/ru/using_api/webhooks/)). В MODX это **`msp3bepaid_public_key`**. Если поле пустое, проверка подписи не выполняется. Basic Auth для webhook всё равно обязателен.

В properties способа те же значения: `store_id`, `secret_key`, `public_key`. Секрет также читается как `secret` или `webhook_secret`. Непустые properties перекрывают системные настройки.

Валюта по умолчанию — BYN. Настройка **`msp3bepaid_test`** после установки уже **Да**. В запрос ссылки уходит `"test": true`. Для боевых платежей выключите её.

## Шаг 2: Заполнение настроек в MODX

1. **Настройки → Системные настройки**, фильтр **`msp3bepaid`**.
2. Заполните Shop ID и секретный ключ. Публичный ключ — по желанию.
3. Для боевых платежей отключите **Тестовый платёж**.
4. После сохранения: **Управление → Очистить весь кэш**.

Список полей: [Системные настройки](settings).

## Шаг 3: Адреса webhook и возврата

В кабинете bePaid укажите адрес уведомлений на магазин:

```text
https://ваш-домен.ru/assets/components/msp3bepaid/webhook.php
```

HTTPS без 301. Пакет при создании ссылки передаёт этот URL в поле `notification_url` токена checkout. Адреса должны совпадать.

Покупатель после оплаты попадает на страницу:

```text
https://ваш-домен.ru/assets/components/msp3bepaid/return.php
```

Пакет подставляет этот адрес в `success_url`, `decline_url`, `fail_url` и `cancel_url` checkout. Страница сверяет токен и может догнать оплату в MiniShop3, если webhook опоздал. Источник истины — webhook.

## Шаг 4: Способ оплаты в MiniShop3

1. В админке MiniShop3: **Настройки → Оплаты**.
2. Включите **Оплата через BePaid**.
3. Привяжите способ к доставке.

Для ERIP заполните тип в **`msp3bepaid_payment_types`** и номер услуги **`msp3bepaid_erip_service_id`** (если требуется).

## Шаг 5: Проверка

1. Оформите заказ и откройте страницу оплаты bePaid.
2. Дождитесь webhook. Без него заказ не оплачен, даже если браузер вернулся на сайт.
3. Возврат во вкладке заказа доступен после уведомления об оплате.

## Тестовые карты

В тестовом режиме (`msp3bepaid_test = Да`) используйте карты из документации bePaid:

| Карта | Сумма | Результат |
| --- | --- | --- |
| `4200 0000 0000 0001` | Любая | Успешная оплата |
| `4200 0000 0000 0002` | Любая | Отказ банка |
| `4200 0000 0000 0003` | Любая | 3-D Secure требуется |

CVC — любое трёхзначное число. Срок действия — любой будущий месяц.
