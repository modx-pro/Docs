# Генерация

## Режимы

У каждого прайса режим лежит в поле **Режим генерации**.

| Режим | Когда пишется файл |
| --- | --- |
| `manual` | Только кнопка генерации в менеджере. Сохранение товара и планировщик этот прайс не берут |
| `scheduler` | Задача планировщика или `cron.php`, если прайс активен и его пора обновить |
| `after_save` | При сохранении, публикации или снятии с публикации товара или категории. Только если товар входит в категории прайса |

Интервал в минутах для `scheduler` и `after_save`. Ноль: только по отметке «нужно сгенерировать». Пустая дата последней генерации при интервале больше нуля считается «пора писать».

Неактивный прайс задачи не берут.

## Планировщик

<!-- MEDIA: screenshot-admin | must | Вкладка «Диагностика»: строки «Планировщик» и «Задача планировщика» в состоянии «ОК» и «Зарегистрирована» | На тестовом стенде с установленным Scheduler и ms3yandexmarket_scheduler_enabled = 1 открыть менеджер «Яндекс Маркет» → «Диагностика» -->

Если установлен Scheduler и настройка `ms3yandexmarket_scheduler_enabled` не равна `0`, открытие менеджера регистрирует задачу `ms3yandexmarket_generate`. Повтор каждый час.

На вкладке **Диагностика** строки **Планировщик** и **Задача планировщика** должны быть «ОК» и «Зарегистрирована».

Успех в журнале Scheduler:

```text
ms3YandexMarket: no pricelists pending generation
```

или по строке на каждый прайс и итог. Запуск не переписывает прайсы в режиме `manual`.

Без Scheduler тот же отбор делает команда:

```bash
php assets/components/ms3yandexmarket/cron.php
```

Свой планировщик сайта должен вызывать `assets/components/scheduler/run.php`. Компонент сам по расписанию MODX не ходит.

## После сохранения товара

<!-- MEDIA: diagram | must | Цепочка после сохранения товара: события MODX/ms3Remains → отметка «нужно сгенерировать» → запись файла (кнопка, планировщик или сразу при ms3yandexmarket_after_save_sync = 1) | Схема по тексту раздела: режимы manual / scheduler / after_save и значение ms3yandexmarket_after_save_sync -->

Плагин слушает `OnDocFormSave`, `OnDocPublished`, `OnDocUnPublished` для товаров и категорий MiniShop3 и событие `ms3remainsOnAfterRemainChange`.

Для `after_save` и `scheduler` он ставит прайсу отметку «нужно сгенерировать», если товар входит в категории прайса. Режим `manual` не отмечается.

В поставке `ms3yandexmarket_after_save_sync` = `0`. Тогда сохранение товара только ставит отметку. Файл пишут планировщик или кнопка. При `1` прайсы `after_save` пишутся в том же запросе. Ошибка записи сохранение товара не откатывает. Отметка остаётся.

Если строки настройки нет, плагин считает `0`. Прайс только отмечается. Файл в том же запросе не пишется.

## Что происходит с файлом

<!-- MEDIA: screenshot-front | must | Готовый YML прайса в браузере по публичному URL файла (фрагмент shop, categories, offer) | На тестовом стенде после успешной генерации открыть URL из карточки прайса, синтетические товары и названия магазина -->

Генерация берёт блокировку на прайс, пишет во временный файл и подменяет итоговый только после завершения. Имя файла всегда `pricelist-{id}.xml`. Каталог задаёт настройка `ms3yandexmarket_files_path`. Он должен быть доступен для записи. Это видно на **Диагностике**. Успешный прогон пишет путь и URL в карточку прайса.

Предпросмотр в менеджере файл на диске не заменяет.

Порция чтения товаров задаёт `ms3yandexmarket_chunk_size` (500). Файл подменяется целиком после порций, не по одной порции на диске.

## Кнопки на вкладке «Генерация»

| Действие | Файл на диске |
| --- | --- |
| **Сгенерировать** | Пишет. Повтор, пока первый запуск держит блокировку, отвечает HTTP 409, код `generation_locked` |
| **Предпросмотр YML** | Не пишет. В ответе число предложений, валидных и пропущенных |
| **Показать сгенерированный YML** и **Скачать YML** | Читают уже записанный файл |

Журнал под кнопками пополняется во время **Сгенерировать**.

## Когда строки нет в YML

Запись из дерева полей:

| Условие | Результат |
| --- | --- |
| Прайс неактивен | Планировщик и `cron.php` его не берут. Кнопка в карточке этого прайса файл пишет |
| Нет `id` | `offer` пропускается |
| Пустой текст тега или тег выключен | Тега в файле нет |
| Цена 0 или пустая при `pipeline:price` | Тега `price` нет. Предложение при этом может остаться |
| Поведение `skip`: нет числа остатка или остаток не выше `min_stock` | Предложение в файл не попадает. Так у нового прайса |

Для Google RSS пустая цена тоже убирает строку. Порог остатка действует и на дереве, и в RSS. См. [состав файла](/components/ms3yandexmarket/feeds).
