# Варианты и остатки

На вкладке **Предложения** задают **Источник предложений** и **Источник остатков**. Таблица под деревом тегов показывает цену, остаток, подпись источника остатка, URL и артикул. Предпросмотр одного `offer` берёт **ID товара** и **ID варианта** над таблицей.

## Источник предложений

<!-- MEDIA: screenshot-admin | must | Вкладка «Предложения»: выпадающие списки «Источник предложений» и «Источник остатков» | На тестовом стенде раскрыть списки: product и variant при ms3Variants; в остатках без пункта custom -->

| Значение | Что попадает в файл |
| --- | --- |
| `product` | Один `offer` на товар MiniShop3 |
| `variant` | Один `offer` на вариант [ms3Variants](/components/ms3variants/). Цена, артикул, картинка и адрес берутся у варианта |
| `combination` | Комбинации [ms3Remains](/components/ms3remains/) без варианта: непустые опции |
| `automatic` | Сначала варианты, иначе комбинации, иначе товар |

## Источник остатков

| Значение | Откуда число |
| --- | --- |
| `minishop3` | Поле остатка товара MiniShop3 |
| `ms3variants` | Остаток варианта |
| `ms3remains` | `RemainServiceInterface::getQuantity`. Нет строки остатка: в файл уходит пусто, не ноль |
| `automatic` | Сначала остаток ms3Remains, если товар им учитывается, иначе вариант, иначе остаток товара |
| `custom` | В списке формы этого пункта нет. Если значение уже лежит в базе, число считается тем же порядком, что `automatic`, а подпись рядом с остатком в таблице равна `custom`, не `ms3remains` / `ms3variants` / `minishop3` |

Явные `ms3remains`, `ms3variants` и `minishop3` не подмешивают другие источники. Нет пакета вариантов или остатков: это видно на [диагностике](/components/ms3yandexmarket/logs). Остаток товара MiniShop3 всё равно читается.

При поведении `skip` порог `min_stock` убирает предложение и из YML дерева, и из RSS. Подробнее: [параметры прайса](/components/ms3yandexmarket/pricelist).
