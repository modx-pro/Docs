# Экраны менеджера

Пункт **Яндекс Маркет** открывает три раздела: **Прайс-листы**, **Логи**, **Диагностика**. Что пишет каждая кнопка: [действия](/components/ms3yandexmarket/actions).

## Список прайсов

<!-- MEDIA: screenshot-admin | must | Список прайсов: поиск, «Создать», колонки ID, название, площадка, файл, дата, активность, статус, кнопки «Изменить» и «Удалить» | На тестовом стенде два прайса, у одного есть file_url, у второго файл ещё не записан -->

Поиск ищет по названию. Пустой список предлагает **Создать**.

| Колонка | Что показывает |
| --- | --- |
| ID | Номер прайса |
| Название | Ссылка в карточку |
| Площадка | `Yandex Market` или `Google RSS 2.0` |
| Файл | Ссылка, если `file_url` заполнен. Иначе пусто |
| Дата | `generated_on` последнего успешного прохода |
| Активен | Да или нет. Планировщик и `cron.php` пропускают выключенный прайс |
| Статус | `success`, `error`, `warning`, `running` последнего запуска |

**Удалить** спрашивает подтверждение и убирает прайс. Файл на диске остаётся. Карточка после удаления недоступна.

## Новый прайс

<!-- MEDIA: screenshot-admin | must | Форма до «Создать»: название, описание, активность, режим, тип оффера, площадка и назначение; вкладок «Предложения» и «Генерация» ещё нет | На тестовом стенде открыть «Создать» без сохранения, синтетическое название -->

До **Создать** видны название, описание, активность, режим, тип оффера, площадка и назначение (для Яндекса). Путь, дерево тегов и предпросмотр появляются после сохранения. Категории можно отметить сразу.

Без названия форма не сохраняется.

Вкладки **Предложения** и **Генерация** есть только у уже созданного прайса. При назначении `placement` вкладки **Категории** нет.

## Вкладка «Магазин»

<!-- MEDIA: screenshot-admin | must | Карточка прайса, вкладка «Магазин»: название, режим, площадка, путь и URL файла, дерево «Поля магазина», условия, панель «XML магазина» | На тестовом стенде прайс yandex.market / catalog с заполненными name, company, url -->

| Поле | Куда пишется |
| --- | --- |
| Название, описание | Карточка прайса. Описание в XML не попадает |
| Активен | Планировщик и `cron.php` пропускают выключенный прайс |
| Режим генерации | `manual`, `scheduler`, `after_save` |
| Тип оффера | `simple` или `vendor.model`. Для YML из дерева полей атрибут `type` из этого поля не ставится |
| Площадка | `yandex.market` или `google.rss20` |
| Назначение файла | Только у Яндекса: `catalog`, `placement`, `items` |
| Путь и URL файла | После записи подменяются на `pricelist-{id}.xml` в каталоге `ms3yandexmarket_files_path` и URL этого файла. До генерации в полях можно хранить свой текст, место записи он не задаёт |
| Управляемые поля | Только при `placement`. Непустой список оставляет в `offer` имена из списка. Имя `available` пишется атрибутом. Атрибут `id` пишется всегда. Пустой список фильтр не включает |

**Сохранить** в шапке пишет эти поля. Теги дерева он не пишет: у тега своя кнопка **Сохранить тег**.

Слева дерево **Поля магазина**. Справа имя тега, источник текста и переключатель **Выводить в файл**. Выключенный тег в списке бледнее и в XML не попадает.

**Добавить атрибут** создаёт атрибут (по умолчанию имя `id`). Кнопки «добавить тег» и «удалить тег» в дереве нет. Набор тегов заполняется при создании прайса по площадке и назначению. Создать или удалить тег можно [маршрутом менеджера](/components/ms3yandexmarket/api).

Под деревом условия с `target` = `resource`. Справа **XML магазина**: фрагмент, файл на диске не заменяется.

## Вкладка «Категории»

Дерево разделов MiniShop3 развёрнуто целиком. У строки флажок выбора. У выбранной строки появляются флажок **Исключена** и поле **Своё название**. Справа предпросмотр блока категорий.

## Вкладка «Предложения»

<!-- MEDIA: screenshot-admin | must | Вкладка «Предложения»: источник предложений, источник остатков, дерево полей offer, id товара и варианта для предпросмотра, таблица предложений с ценой, остатком, URL и артикулом | На тестовом стенде offer_source = variant, в таблице несколько строк -->

**Источник предложений** и **Источник остатков** задают, сколько `offer` будет у товара и откуда возьмётся число остатка. Значения: [варианты и остатки](/components/ms3yandexmarket/variants). В списке остатков нет пункта `custom`.

Дерево **Поля предложения** устроено так же, как поля магазина. Условия под ним пишутся с `target` = `offer`.

**ID товара** и **ID варианта** выбирают строку для панели XML одного предложения. Таблица ищет товары выборки: ID, название, цена и старая цена, остаток и его источник, URL, артикул. Страницы по 20 строк.

## Вкладка «Генерация»

<!-- MEDIA: screenshot-admin | must | Вкладка «Генерация»: статус и дата последнего запуска, отметка «нужно сгенерировать», кнопки «Сгенерировать», «Предпросмотр YML», «Показать» и «Скачать», журнал под кнопками во время записи | На тестовом стенде запустить «Сгенерировать» и снять кадр с непустым журналом на синтетическом прайсе -->

**Сохранить настройки** пишет режим, интервал, площадку, путь и URL. Те же режим и площадка есть на **Магазине**.

Над кнопками: статус, дата, число выгруженных, число ошибок, ссылка на файл, отметка «нужно сгенерировать».

| Кнопка | Что делает |
| --- | --- |
| **Сгенерировать** | Пишет файл. Пока идёт запись, второй запуск того же прайса отвечает `generation_locked` |
| **Предпросмотр YML** | Собирает XML в памяти. Показывает число предложений, валидных и пропущенных. Файл на диске не меняет |
| **Показать сгенерированный YML** | Читает уже записанный файл |
| **Скачать YML** | Отдаёт тот же файл как загрузку |

Под кнопками журнал текущего запуска. До **Сгенерировать** он пустой.
