# Журнал и диагностика

## Журнал

<!-- MEDIA: screenshot-admin | must | Раздел «Логи»: таблица запусков со статусом, счётчиками выгруженных и пропущенных предложений, фильтр по прайсу | На тестовом стенде после одной успешной и одной частично неуспешной генерации на синтетическом прайсе -->

В **Логах** запуски генерации. Колонки: номер, прайс, статус, старт, выгружено, ошибки, предупреждения, длительность. **Подробнее** открывает сообщения этого запуска.

| Статус | Когда |
| --- | --- |
| `running` | Запись ещё идёт |
| `success` | Файл записан, ошибок в журнале нет |
| `error` | В журнале есть ошибки или запись оборвалась исключением |
| `warning` | Есть в перечислении статусов и в подписи интерфейса. У нового прайса счётчик предупреждений всегда 0, поэтому завершённый прогон этот статус не получает |

Опрос вкладки **Генерация** останавливается на `success`, `error` и `partial`. Статус `partial` сервер не присылает.

Фильтр по номеру прайса сохраняется после **Обновить**. Карточка запуска ведёт на прайс.

Потолок числа сообщений одного запуска задаёт `ms3yandexmarket_log_entry_cap` (200).

## Карточка запуска

<!-- MEDIA: screenshot-admin | must | Карточка запуска журнала: статус, выгружено, длительность, размер файла, ссылка на прайс, таблица сообщений (уровень, сущность, поле, текст) | На тестовом стенде после генерации с предупреждениями или ошибками по полям открыть «Подробнее» у записи на синтетическом прайсе -->

**Детали** открывает один запуск. Сверху статус, число выгруженных, длительность и размер файла. Ниже номер прайса (ссылка в карточку), время старта и финиша, пропущено, ошибки, предупреждения.

Таблица сообщений: уровень, сущность (`тип:id`), поле и текст. Пустая таблица значит, что замечаний по полям не было. **Назад** возвращает к списку.

## Диагностика

<!-- MEDIA: screenshot-admin | must | Вкладка «Диагностика»: таблица строк PHP, MiniShop3, pdoTools, Scheduler, ms3Variants, каталог YML | На тестовом стенде с полным набором зависимостей, все строки без сбоя -->

Вкладка **Диагностика** проверяет среду, а не файл прайса.

| Строка | Что значит сбой |
| --- | --- |
| PHP, версия компонента, размер порции | Порция: `ms3yandexmarket_chunk_size` |
| MiniShop3 | Без него товары не читаются |
| pdoTools Fenom | Без него значения `fenom:` не считаются |
| Планировщик | Пакет Scheduler не найден. Используйте `cron.php` |
| Задача планировщика | Пакет есть, задача `ms3yandexmarket_generate` не создана. Откройте менеджер компонента ещё раз при включённой настройке `ms3yandexmarket_scheduler_enabled` |
| ms3Variants, ms3Remains | Пакет не стоит. Соответствующий источник предложений или остатка недоступен |
| Служба вариантов | Пакет ms3Variants установлен, а сервис вариантов в MODX не зарегистрирован |
| Остаток варианта | Пакет установлен, а сервис остатка варианта не зарегистрирован |
| Служба остатков | Пакет ms3Remains установлен, а сервис остатков не зарегистрирован |
| Идентичность остатка | Пакет установлен, а резолвер идентичности остатка не зарегистрирован |
| Каталог YML | Процесс PHP не может писать в каталог файлов |

Если пакет вариантов или остатков не установлен, четыре служебные строки не считаются сбоем. Сбой: «нет» при установленном пакете.

## Пустой магазин в предпросмотре

<!-- MEDIA: screenshot-admin | nice | Предпросмотр XML с фрагментом `<shop><offers/></shop>` при незаполненных тегах name, company, url | На тестовом стенде новый прайс до сохранения источников тегов магазина -->

`<shop><offers/></shop>` при живых товарах значит, что у тегов `name`, `company` и `url` не выбран источник. Заполните **Откуда брать текст** и нажмите **Сохранить тег**.
