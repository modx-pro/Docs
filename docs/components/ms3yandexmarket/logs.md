# Журнал и диагностика

## Журнал

![Раздел «Логи» ms3YandexMarket](/components/ms3yandexmarket/screenshots/logs.png)

В **Логах** лежат запуски генерации. **Подробнее** открывает сообщения запуска. Колонки:

- номер
- прайс
- статус
- старт
- выгружено
- ошибки
- предупреждения
- длительность

| Статус | Когда |
| --- | --- |
| `running` | Запись ещё идёт |
| `success` | Файл записан, ошибок в журнале нет |
| `error` | В журнале есть ошибки или запись оборвалась исключением |
| `warning` | Ошибок нет, предупреждения есть. Файл записан |

Опрос вкладки **Генерация** останавливается на `success`, `error`, `warning` и `partial`. Статус `partial` сервер не присылает.

Предупреждение пишется в таких случаях:

- описание длиннее 6000 символов
- штрихкод не EAN, UPC, ISBN или Code 128
- `oldprice` не выше цены или скидка вне 5–99%
- картинка не абсолютный `http(s)` или её хост не совпадает с URL магазина
- у `delivery-options` или `pickup-options` больше пяти `option`

Лишние `option` в файл не попадают. Остальной текст при warning пишется.

Повторный `id` даёт ошибку `Duplicate offer id`. Это предложение в файл не попадает. Отметка «нужно сгенерировать» снимается только если статус не `error`.

Фильтр по номеру прайса сохраняется после **Обновить**.

Потолок числа сообщений одного запуска задаёт `ms3yandexmarket_log_entry_cap` (200).

## Карточка запуска

![Карточка запуска ms3YandexMarket](/components/ms3yandexmarket/screenshots/logs-2.png)

![Карточка запуска ms3YandexMarket](/components/ms3yandexmarket/screenshots/logs-3.png)

**Детали** открывает один запуск.

| Блок | Что видно |
| --- | --- |
| Сверху | Статус, число выгруженных, длительность, размер файла |
| Ниже | Номер прайса (ссылка в карточку), время старта и финиша, пропущено, ошибки, предупреждения |
| Сообщения | Уровень, текст и при наличии строка `тип id · поле` |

Пустой список: замечаний по полям не было. Живой журнал на вкладке **Генерация** берёт из того же списка последние 80 записей. **Назад** возвращает к списку запусков.

## Диагностика

![Вкладка «Диагностика» ms3YandexMarket](/components/ms3yandexmarket/screenshots/diagnostics.png)

Вкладка **Диагностика** проверяет среду, а не файл прайса.

| Строка | Что значит сбой |
| --- | --- |
| PHP, версия компонента, размер порции | Порция: `ms3yandexmarket_chunk_size` |
| MiniShop3 | Без него товары не читаются |
| pdoTools Fenom | Без него значения `fenom:` не считаются |
| Планировщик | Пакет Scheduler не найден. Используйте `cron.php` |
| Задача планировщика | Пакет есть, задача `ms3yandexmarket_generate` не создана. Откройте менеджер компонента ещё раз при включённой настройке `ms3yandexmarket_scheduler_enabled` |
| ms3Variants, ms3Remains | Пакет не стоит. Соответствующий источник предложений или остатка недоступен |
| Сервис вариантов | Пакет ms3Variants установлен, а сервис вариантов в MODX не зарегистрирован |
| Склад вариантов | Пакет установлен, а сервис остатка варианта не зарегистрирован |
| Сервис остатков | Пакет ms3Remains установлен, а сервис остатков не зарегистрирован |
| Идентичность остатка | Пакет установлен, а резолвер идентичности остатка не зарегистрирован |
| Каталог YML | Процесс PHP не может писать в каталог файлов |

Если пакет вариантов или остатков не установлен, четыре служебные строки не считаются сбоем. Сбой: «нет» при установленном пакете.

## Пустой магазин в предпросмотре

![Предпросмотр XML ms3YandexMarket](/components/ms3yandexmarket/screenshots/empty-shop.png)

`<shop><offers/></shop>` при живых товарах значит: у тегов `name`, `company` и `url` не выбран источник. Заполните **Откуда брать текст** и нажмите **Сохранить тег**.
