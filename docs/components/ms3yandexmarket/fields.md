# Поля файла

## Вкладка «Магазин»

<!-- MEDIA: screenshot-admin | must | Вкладка «Магазин»: список «Поля магазина» слева, настройки тега справа, блок «XML магазина» | На тестовом стенде открыть прайс tree_v2 с заполненными тегами name, company, url -->

**Поля магазина** задают теги внутри `shop`: слева список, справа настройки выбранного тега. **XML магазина** показывает фрагмент для файла.

Имя справа (`<name>` и подобные) это имя тега в XML. **Текст**: тег получает строку внутрь. **Предложения**: тег группирует вложенные теги без своего текста.

**Сохранить** в шапке пишет название, путь и режим прайса. **Сохранить тег** пишет только выбранный тег.

## Откуда брать текст

<!-- MEDIA: snippet-config | must | Примеры строк «Откуда брать текст»: field:pagetitle, data:price, value:…, setting:site_url для тегов магазина и offer | Фрагмент настройки тега в менеджере (скрин или подписи полей), без оформления сайта -->

Выберите поле товара или введите своё значение. Формат: `тип:ключ`. Примеры: `field:pagetitle`, `data:price`, `value:Мой магазин`, `setting:site_url`.

Если источник не выбран, в XML тег пустой. У нового прайса теги `name`, `company` и `url` пустые, поэтому предпросмотр выглядит как `<shop><offers/></shop>`.

Переключатель **Выводить в файл** выключает тег, не удаляя его из списка. Выключенный тег в списке слева бледнее.

**Имя тега** меняет имя в XML. **Добавить атрибут** добавляет свойство тега, например `id`.

Полный список префиксов: [источники значений](/components/ms3yandexmarket/sources).

У тега магазина разбираются только `setting:` и `value:`. Строка `field:pagetitle` или `data:price` в теге магазина попадёт в XML как введённый текст. Пустой источник подставляет одноимённый ключ `shop_settings` (`name`, `company`, `url`). У нового прайса эти ключи пустые, поэтому тег не пишется.

## Типы тега

Число хранится в базе. В карточке видно русское имя.

| Число | В карточке | Что пишется |
| --- | --- | --- |
| 0 | Текст | Текст внутри тега, спецсимволы экранируются |
| 12 | Текст без разметки | То же в секции CDATA. Так создаётся `description` каталога |
| 13 | Картинка | URL картинки внутри тега |
| 19 | Свой XML | Фрагмент как есть, после проверки |
| 11 | Значение | Текст, как у обычного тега |
| 1, 2, 4, 5, 6, 7, 10 | Корень, магазин, категории, предложения, предложение, категория, группа | Контейнер. Своего текста нет, внутри вложенные теги |
| 3 | Валюты | Контейнер. Профиль Яндекса его не создаёт |
| 14, 15 | Категории, предложения | Прозрачный контейнер: группа без своего текста |
| 20 | Пустой | Контейнер без текста |

Тег с именем `id` внутри шаблона предложения не становится вложенным элементом. Его текст уходит в атрибут `id`. Тег `available` уходит в атрибут `available`. Пустой текст оба атрибута не ставит.

Атрибуты, заданные у узла `offer` (кроме `id` и `available`), пишутся как есть. Поле **Тип оффера** в шапке к ним не относится.

## Поля предложения

Теги блока **Поля предложения** попадают в каждый `offer` (название, цена, url, артикул, картинка).

`pipeline:url`, `pipeline:image`, `pipeline:price`, `pipeline:old_price`, `pipeline:vendor` считают значения по правилам компонента. Фиксированный текст: префикс `value:`.

## Свой XML и Fenom

<!-- MEDIA: snippet-code | must | Пример тега типа RAW_XML (19) и обработчика Fenom с префиксом fenom: для поля offer | Минимальный XML-фрагмент и шаблон Fenom, которые проходят проверку; права edit_raw_xml и edit_fenom на стенде -->

Тип тега `19` пишет в файл фрагмент XML как есть. Перед сохранением фрагмент проверяется: пустая строка допустима, битый XML нет. Несколько соседних тегов без общего корня тоже проходят проверку.

Префикс `fenom:` и непустой обработчик тега считаются через pdoTools. PHP в таком тексте не выполняется.

Сохранение типа `19` требует права `ms3yandexmarket_edit_raw_xml`. Сохранение обработчика требует `ms3yandexmarket_edit_fenom`. Без права ответ 403. Оба ключа установщик кладёт в политику. См. [настройки и права](/components/ms3yandexmarket/settings).
