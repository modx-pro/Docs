# Настройки контекстов

Контекст определяет область материалов и соответствие полей результата полям
ресурса MODX. Задачу можно создать только для включённого и корректно
настроенного контекста.

## Область блога

Можно использовать весь контекст или выбрать один либо несколько корневых
разделов. При выборе разделов ContentFlow учитывает только их поддеревья.

Нельзя одновременно выбирать родительский раздел и вложенный в него раздел.

## Конечные категории

Конечной считается категория, которая:

- имеет `isfolder = 1` либо `class_key = CollectionContainer`;
- не содержит дочерних категорий.

Обычные дочерние документы не мешают категории считаться конечной.

Content Manager получает полный путь категории от настроенного корня, например:

```text
Блог → Смартфоны
Инструкции → VPS
Обзоры → VPS
```

Это позволяет различать одинаково названные категории в разных ветках.
Неопубликованная категория также может участвовать в планировании, если она не
удалена, находится в настроенной области и соответствует правилам конечной
категории.

## Сопоставление полей

Для каждого результата укажите поле ресурса MODX или TV:

| Результат | Значение по умолчанию |
|---|---|
| Заголовок | `pagetitle` |
| Alias | `alias` |
| Description | `description` |
| Краткое описание | `introtext` |
| Текст | `content` |
| Главное изображение | `tv.image` |

TV указывается в формате `tv.name`, без MODX-тегов.

Одно поле назначения нельзя использовать сразу для нескольких результатов.

## Длина заголовка и Description

Диапазоны задаются в формате `МИН-МАКС`, например:

```text
40-80
140-160
```

При проверке допускается отклонение до 10% в обе стороны. Диапазон Introtext и
целевой объём Content задаются отдельно в задаче.

## Формирование alias

Доступны режимы:

- **MODX** — модель оставляет alias пустым, его формирует MODX;
- **На языке материала** — модель возвращает URL slug на языке статьи;
- **Транслитерация** — модель возвращает латинскую транслитерацию;
- **Английский** — модель передаёт смысл заголовка английским URL slug.

ContentFlow проверяет уникальность alias при создании ресурса. Если такой alias
уже существует, к новому добавляется числовой суффикс.

Для режима MODX в контексте должен корректно работать `automatic_alias`, если
включены дружественные URL.

## Папка изображений

Путь задаётся от корня сайта, например:

```text
/assets/uploads/articles/
```

Для каждого ресурса создаётся отдельный каталог с его ID. PHP CLI должен иметь
право записи в базовую папку.

## Синтаксис чанков

Настройка определяет вид офферов и рекламных вставок:

- MODX: `[[$ChunkName]]`;
- Fenom: `{include 'ChunkName'}`.

В задаче указывается только имя чанка. Готовый тег формируется ContentFlow и
передаётся агенту без возможности заменить его вызовом сниппета.
