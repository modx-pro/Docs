# Основные понятия

## Задача

Задача хранит правила подготовки материалов: контекст, категории, расписание,
параметры публикации, инструкции и переопределения моделей.

ContentFlow поддерживает два типа задач:

- **Автоматическая** — Content Manager создаёт темы, задача может запускаться по
  расписанию;
- **Ручная** — темы добавляет пользователь, запуск создаётся вручную.

Тип существующей задачи изменить нельзя. Чтобы использовать её настройки с
другим типом, клонируйте задачу.

## Карта контента

Карта контента — список тем задачи. Тема существует независимо от статьи и
может ожидать принятия, проверки дублей или запуска.

Когда pipeline подготовил материал, с темой связываются внутренняя запись статьи
и ресурс MODX. Поэтому одна таблица показывает как ещё не написанные темы, так и
результаты публикации.

## Запуск

Запуск — одна попытка обработать определённый набор тем. При создании запуска
ContentFlow сохраняет снимок конфигурации (snapshot).

Снимок содержит настройки задачи, контекста и агентов на момент запуска. Если
после этого изменить задачу или промпт, активный запуск продолжит работать со
старой конфигурацией. Новые значения получит следующий запуск.

## Статья и ресурс MODX

Статья — внутренняя запись ContentFlow с результатом pipeline. Ресурс MODX
создаёт Publisher. Если после создания ресурса произошла ошибка изображения или
финализации, черновик сохраняется и Publisher можно повторить отдельно.

## Агент

Агент определяет роль, промпты и используемую модель. Набор ролей фиксирован:

1. Контент-менеджер;
2. Копирайтер;
3. Технический редактор;
4. Ревьюер;
5. Publisher.

## Модель и версия

Модель — модуль подключения к поставщику API. Версия — конкретный идентификатор
модели у поставщика, например текстовая, графическая или Embeddings-модель.

Настройки подключения сохраняются в модели. Агент выбирает модель, версию и
параметры генерации. Задача может переопределить этот выбор, не копируя API-ключ.

## Статусы не заменяют друг друга

Для темы отдельно хранятся:

- решение пользователя: ожидает, принята или отклонена;
- результат dedup;
- состояние обработки;
- состояние связанного ресурса MODX.

Поэтому, например, принятая тема может одновременно иметь статус dedup
«Требует уточнения» и не попадёт в pipeline до решения пользователя.
