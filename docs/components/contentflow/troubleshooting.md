# Решение проблем

## Worker обработал 0 элементов

Сообщение:

```text
ContentFlow worker ... processed 0 work item(s).
```

Проверьте:

1. включён ли ContentFlow в глобальных настройках;
2. создан ли запуск и находится ли он в очереди;
3. включена ли автоматическая задача для плановых запусков;
4. есть ли принятые темы, прошедшие dedup;
5. не исчерпан ли дневной лимит.

## Не выбрана обязательная модель

Каждому текстовому агенту требуется включённая и настроенная текстовая модель.
Кроме того, в глобальных настройках должны быть выбраны Embeddings-модель и LLM
проверки дублей.

Если задача переопределяет профиль агента, проверьте её собственную вкладку
**Переопределение моделей**.

## Глобальный прокси не указан

Модель с режимом **Глобальный прокси** требует заполненного адреса в глобальных
настройках. Либо заполните адрес, либо выберите прямое подключение или
собственный прокси.

## Content Manager исчерпал лимит веб-поиска

Сообщение содержит:

```text
exhausted the web-search tool-call limit
```

Один лимит расходуют `search`, `open_page` и `find_in_page`. Увеличьте максимум
вызовов для профиля Content Manager либо сократите число источников и обязательных
проверок в инструкции задачи.

Для новостной задачи не используйте большой запас тем без необходимости: каждый
задействованный раздел выполняет отдельный запрос с веб-поиском.

## Не подтверждены источники темы

Если включены обязательный веб-поиск и передача источников, ContentFlow принимает
только URL, которые присутствуют в ответе поставщика как реально открытые.

Ошибка означает, что модель вернула тему или URL, который не удалось связать с
подтверждённым источником. Проверьте:

- достаточен ли лимит веб-вызовов;
- открываются ли указанные сайты у поставщика поиска;
- не требует ли инструкция слишком много тем за один запрос;
- не заставляет ли промпт искать отдельное подтверждение для каждого факта.

## article_output_invalid

Сообщение журнала указывает этап и причину. Например:

```text
article_output_invalid: stage=copywriter;
reason=empty_required_fields=title,description,introtext
```

Проверьте промпт указанного агента и выбранную модель. Она должна поддерживать
структурированный ответ и возвращать полную запись статьи, а не пояснение или
фрагмент исправления.

## Статья слишком короткая

`content_too_short` означает, что чистый текст Content не достиг 90% целевого
объёма задачи. Уменьшите цель либо уточните инструкцию Копирайтеру. Не снижайте
контроль только ради прохождения явно неполной статьи.

## Ревьюер исчерпал циклы

Откройте журнал темы и сравните причины всех возвратов. Частые причины:

- тема шире подготовленного материала;
- противоречивая инструкция задачи;
- неподтверждённые факты;
- неверный alias;
- выход за допустимую длину полей;
- ссылки или Markdown, запрещённые правилами задачи.

Исправьте промпт или инструкцию и верните ошибочную тему в новый запуск, если
ресурс MODX ещё не создан.

## Ошибка дополнительных изображений

Проверьте полный текст события журнала. Для Recraft итоговый промпт не должен
превышать 1000 символов. Если ресурс уже создан, используйте **Повторить
Publisher** — текстовая часть статьи не будет генерироваться заново.

## В ресурсе остался contentflow:image

Publisher намеренно запрещает завершение, если в Content остался маркер:

```html
<!-- contentflow:image:1 | ... -->
```

Проверьте модель изображений, промпт и права на запись. Не публикуйте ресурс
автоматически с незаменённым техническим маркером.

## Ресурс появился, но ссылка не обновилась на сайте

Publisher очищает кэш ресурса и контекста после финализации. Если сторонний
сниппет использует собственный кэш, очистите его в обработчике
`OnContentFlowResourcePublished` либо настройте событие соответствующего
компонента.

## Cron работает из SSH, но не срабатывает по расписанию

Укажите абсолютные пути к PHP и MODX. Проверьте пользователя cron, права на
файлы, версию PHP CLI и часовой пояс. Перенаправьте вывод команды во временный
файл на время диагностики.

## Ошибка загрузки modprocessor.class.php

Путь `core/model/modx/modprocessor.class.php` относится к старому API MODX 2.
ContentFlow рассчитан на MODX 3 и сам этот файл не подключает. Ошибка обычно
возникает в стороннем устаревшем дополнении или кастомном процессоре.

## Ошибка установки индекса MySQL

Таблицы ContentFlow должны создаваться в InnoDB. Если MySQL сообщает о слишком
длинном ключе для MyISAM, убедитесь, что устанавливается актуальный пакет
ContentFlow 1.0.0-pl, удалите только распакованный кэш неудачной установки из
`core/packages/contentflow-1.0.0-pl/` и повторите установку пакета.

Не удаляйте рабочие таблицы ContentFlow перед обычным обновлением.
