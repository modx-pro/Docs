# Задачи

Задача объединяет темы, правила подготовки материалов и параметры публикации.
Новая задача создаётся выключенной и ничего не запускает до явной команды.

## Создание задачи

На странице **Задачи** нажмите **Создать задачу**. Форма разделена на четыре
вкладки:

1. Задача;
2. Контент и публикация;
3. Ссылки, офферы и вставки;
4. Переопределение моделей.

## Типы задач

### Автоматическая

Content Manager распределяет и генерирует темы. Доступны расписание, дневной
лимит, запас тем и правила выбора категорий.

### Ручная

Темы вводит пользователь. Content Manager пропускается, расписание отсутствует,
а запуск создаётся вручную. В одну ручную задачу можно добавлять новые темы и
использовать её повторно.

Тип сохранённой задачи изменить нельзя. При клонировании тип можно выбрать
заново, потому что создаётся новая задача без истории.

## Планирование автоматической задачи

### Периодичность

Задача запускается ежедневно либо только по выбранным дням недели. Время
рассчитывается по часовому поясу сервера.

### Запас тем

Количество тем, которое Content Manager создаёт, когда в карте не осталось
доступных тем.

Это не дневной лимит. Если указать запас `100`, Content Manager действительно
распределит и подготовит 100 тем. Для новостей обычно разумно использовать
небольшой запас, чтобы темы не устаревали.

### Дневной лимит статей

Максимальное количество статей автоматической задачи за календарные сутки,
независимо от количества ручных и плановых запусков. Значение `0` снимает
дневное ограничение.

Ручная задача обрабатывает все принятые доступные темы выбранного запуска и не
растягивает их по календарным дням.

## Категории автоматической задачи

Доступны два режима:

- **Все конечные категории** — ContentFlow сам находит конечные категории в
  области контекста;
- **Выбранные категории** — пользователь перечисляет ID конечных категорий.

В первом режиме можно исключить ID. Исключение родительского ресурса исключает
всё его поддерево.

## Начальные темы ручной задачи

Одна строка соответствует одной теме:

```text
ID категории | Название темы
```

Строка разделяется только по первому символу `|`, поэтому сам заголовок может
содержать этот символ.

При создании выполняется проверка точных совпадений. Совпавшие темы не
добавляются, а пользователь получает список пропусков до подтверждения формы.

## Обработка новых тем

Для автоматической задачи доступны варианты:

- **Писать сразу** — уникальные темы принимаются и могут попасть в текущий
  запуск;
- **Только после принятия** — темы добавляются в карту и ожидают решения
  пользователя.

После принятия тем ContentFlow создаёт отдельный запуск через cron с
учётом дневного лимита.

## Контент и публикация

### Язык

Используется код языка, например `ru`, `en` или `de`. Он передаётся всем
участникам pipeline и в промпт изображений.

### Шаблон и автор

Publisher применяет выбранный шаблон MODX. Выбранный активный пользователь
записывается в `createdby`, а при автоматической публикации — также в
`publishedby`.

### Размеры полей

- Introtext задаётся диапазоном `МИН-МАКС`;
- Content задаётся целевым количеством символов чистого текста.

Для Content обязательная нижняя граница на 10% меньше цели. Превышение не
ограничивается, если материал остаётся содержательным. Значение `0` отключает
контроль Content, `0-0` отключает контроль Introtext.

### Режим подготовки

- **Максимальный**: Копирайтер → Технический редактор → Ревьюер;
- **Умеренный**: Копирайтер готовит финальный HTML и сразу передаёт его Ревьюеру,
  а Технический редактор подключается только для исправлений.

Умеренный режим дешевле, но Копирайтер получает больше технических требований.

### Публикация

- **Публиковать автоматически** — ресурс публикуется после успешного завершения
  всех этапов;
- **Создавать неопубликованный ресурс** — Publisher сохраняет готовый черновик.

### Изображения

Главное изображение включается отдельно. Количество дополнительных изображений
задаёт верхний предел: при значении `3` модель может выбрать от нуля до трёх.

## Инструкции

Автоматическая задача содержит два независимых поля:

- дополнительная инструкция Контент-менеджеру;
- дополнительная инструкция Копирайтеру.

Инструкция Копирайтеру также передаётся Техническому редактору и Ревьюеру.
Инструкция Контент-менеджеру не попадает в статью.

## Переопределение моделей

Для каждого агента можно оставить профиль по умолчанию или выбрать другую
модель, версию и объявленные модулем параметры. Publisher нельзя отключить как
роль; отсутствие модели изображений допустимо только для задачи без изображений.

## Редактирование и снимок запуска

Изменение задачи не затрагивает активный или уже созданный запуск. Следующий
запуск получит новый снимок конфигурации.

Контекст нельзя изменить после появления тем, запусков или статей. Для другого
контекста клонируйте задачу.

## Клонирование

Клонирование доступно из контекстного меню строки задачи. В новую форму
переносятся настройки, но не переносятся:

- ID;
- темы и статьи;
- запуски;
- журнал;
- состояние автозапуска.

Клон ничего не создаёт до нажатия **Сохранить**.

## Страница задачи

После сохранения задача открывается на отдельной странице:

- **Обзор** — состояние, расписание, последний запуск, счётчики и последние
  ошибки;
- **Запуски** — история запусков и зафиксированная конфигурация каждого из них;
- **Карта контента** — темы, статьи, статусы dedup и ресурсы MODX;
- **Журнал** — события с фильтрами по запуску, теме, агенту и этапу.

Кнопка **Редактировать** открывает настройки задачи на отдельной странице. Меню
**Действия** содержит только команды, допустимые для текущего типа и состояния:
ручной запуск, остановку, включение или выключение расписания, архивирование и
восстановление.

## Архив и удаление

Архивная задача не запускается, не изменяется и не участвует в планировании.
После восстановления автозапуск остаётся выключенным.

Безвозвратное удаление доступно только из архива. Оно удаляет внутреннюю историю
ContentFlow, но не удаляет созданные ресурсы MODX и файлы изображений.
