# Изображения

Изображения создаёт Publisher после сохранения текстового черновика MODX.

## Главное изображение

Если в задаче включено главное изображение, Publisher:

1. берёт Title и Introtext готовой статьи;
2. формирует промпт по шаблону Publisher;
3. вызывает выбранную графическую модель;
4. сохраняет файл в каталоге ресурса;
5. записывает путь в поле изображения из настроек контекста.

Если при повторе Publisher поле уже заполнено, изображение не создаётся заново.

## Дополнительные изображения

Задача задаёт верхний предел дополнительных изображений. Технический редактор сам
решает, сколько изображений нужно конкретной статье, и размещает после
подходящих абзацев маркеры:

```html
<!-- contentflow:image:1 | Конкретное описание сцены -->
```

Publisher извлекает только описание сцены, дополняет его правилами из промпта
Publisher и передаёт графической модели.

После генерации маркер заменяется на:

```html
<p><img src="/assets/uploads/articles/123/content-1.webp"
    alt="Заголовок раздела" loading="lazy"></p>
```

Каждая замена сразу сохраняется в ресурсе. Если третье изображение завершилось
ошибкой, первые два уже находятся в статье и при повторе не генерируются.

За один проход обрабатывается не более 20 дополнительных изображений на
статью. Для обычного материала рекомендуется значительно меньшее значение.

## Промпт дополнительных изображений

Описание сцены должно быть самодостаточным и относиться к абзацу, возле которого
поставлен маркер. Общий шаблон Publisher задаёт правила текста, брендов,
инфографики и языка изображения.

Для Recraft итоговый промпт ограничивается 1000 символами. ContentFlow сокращает
вставленное описание сцены с учётом длины общего шаблона. Если сам шаблон уже
занимает весь лимит, Publisher завершится с ошибкой конфигурации.

## Каталог файлов

Изображения сохраняются по схеме:

```text
{базовый путь}/{ID ресурса}/main.ext
{базовый путь}/{ID ресурса}/content-1.ext
{базовый путь}/{ID ресурса}/content-2.ext
```

Запись выполняется через временный файл и атомарное переименование. При удалении
задачи или темы ContentFlow не удаляет файлы изображений автоматически.

## Ошибка Publisher

Если изображение не создано:

- ресурс остаётся неопубликованным;
- статья получает статус **Завершена с ошибками**;
- в карте контента доступно действие **Повторить Publisher**.

Publisher не завершит публикацию, пока в Content остаётся любой маркер
`contentflow:image`, в том числе повреждённый или незакрытый.
