# Глобальные настройки

Глобальные настройки действуют на весь компонент. Изменения применяются к новым
запускам; уже созданные snapshot не изменяются.

## Основные

### Включить ContentFlow

Главный выключатель обработки. Когда он выключен, scheduler не создаёт новые
запуски, а worker не должен использоваться для штатной обработки.

### Автоматическая приостановка

Останавливает систему после заданного количества последовательных системных
ошибок. К таким ошибкам относятся недоступность API, временные ошибки сервиса и
другие сбои инфраструктуры, а не обычное решение Ревьюера вернуть статью на
доработку.

### Максимальное количество попыток

Общее количество попыток одного запроса к модели, включая первую. Повторяются
только ошибки, которые можно безопасно считать временными. Ошибка конфигурации
или невалидный структурированный ответ не повторяются бесконечно.

### Путь к скрипту cron

Информационное поле содержит абсолютный путь к `cron.php` текущей установки.
Путь не сохраняется в системных настройках и вычисляется автоматически.

Скрипт следует запускать через PHP CLI каждую минуту. Для обычной работы
параметры не требуются; `--schedule-only` выполняет только планирование, а
`--once` ограничивает обработку одним элементом очереди.

## Глобальный HTTP-прокси

Поддерживается HTTP-прокси в одном из форматов:

```text
LOGIN:PASSWORD@IP:PORT
http://LOGIN:PASSWORD@IP:PORT
```

В настройках каждой модели можно выбрать прямое подключение, глобальный прокси
или собственный HTTP-прокси.

## Параметры Content Manager

### Тем целевой категории в запросе

Максимальное количество существующих, запланированных и ранее отклонённых тем
целевой категории, которые Content Manager получает перед генерацией новых тем.

Большое значение уменьшает риск повторов в крупных разделах, но увеличивает
размер запроса. По умолчанию передаётся до 500 тем.

### Тем остальных категорий в запросе

Общий лимит тем из остальных категорий задачи. Темы распределяются между ними
равномерно и помогают не создавать один материал в нескольких соседних
разделах. Это общий лимит, а не лимит для каждой категории.

## Логирование

Настройки логирования задают уровень, срок хранения и ограничения файловых
журналов. Операционный журнал задач дополнительно хранится в базе данных и
доступен в интерфейсе ContentFlow.

Не включайте уровень `debug` постоянно на рабочем сайте. Он предназначен для
диагностики и быстрее заполняет журнал.

## Уведомления

Telegram и Email настраиваются в этой же форме. Для каждого канала доступна
кнопка проверки отправки. Подробнее см. [Уведомления](notifications).
